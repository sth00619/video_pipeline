- `보존 후보`: 장면 의미·공간 구성·콘텐츠 밀도가 다음 영상의 기준으로 쓸 수 있다. 문자·캐릭터 세부 결함은 별도 교정한다.

- 아래 판정은 사용자의 최종 취향 승인이 아니라, 승인 대사와 저장소 계약에 대한 기술 감사 결과다.

### 문자·숫자 판정 원칙

- 대본과 `screen_texts`에 승인된 한국어·영어 비수치 문구는 이미지 모델이 자연스러운 물리 표면에 직접 쓸 수 있다. 출처가 이미지 모델이라는 사실은 실패 원인이 아니다.
- 정확한 승인 문자열이 빠지거나 훼손되거나 번역·중복되거나, 현재 장면에 없는 문구·기업·티커가 추가되면 실패다.
- 지수값·등락률 등 금융 수치는 프로젝트 전역 안전 규칙에 따라 검증 사실 원문만 Pillow/FFmpeg로 렌더링한다. 이 경로도 현재 장면 대사에 그 값이 실제 등장할 때만 선택한다.
- OCR은 빠른 1차 게이트일 뿐이다. 스타일화된 한국어를 놓칠 수 있으므로 최종 멀티모달 검수가 화면의 모든 한글·영문·숫자를 직접 전사하고 허용 목록과 대조한다.

- scene08의 얼굴 문제는 다른 장면과 다른 캐릭터 종처럼 보인다는 연속성 오류였지, 모든 장면에 한 얼굴과 금융 진행자 의상을 복제하라는 요구가 아니었다.
- 정확한 문구, 무관 문구 차단, 손·팔 오류 검출, 말풍선 계획 여부는 품질 게이트다. 이 항목들을 하나의 고정된 미술 프롬프트로 합치지 않는다.
- 표정, 눈 모양의 감정 변화, 의상, 모자, 캐릭터 크기와 위치, 분할 구도, 색감, 정보 표면 개수, 텍스트 위계는 장면별로 달라질 수 있다.
- 기존 기본 참조인 단독 캐릭터 시트·추상 붓자국 시트·흰 스티커형 장면 참조는 Job 52의 실제 장면 범위와 달라 기본 전송에서 제외했다.
- 기본 참조는 scene04·06·18·29·43의 실제 장면으로 교체했다. 이 다섯 장은 절대 모델시트가 아니라 서로 다른 캐릭터 역할·색·구도·정보 밀도가 허용되는 채널 화풍 범위다.
- 과거 자동 규칙인 오른쪽 전경 캐릭터, 35% 고정 크기, 남색 정장·페도라, 단일 정보판, 소품 최소 3개, 무조건 연속 공간, 배경 인물 금지는 철회했다.

## 잘된 생성 과정에서 공통으로 확인된 조건

1. 대사의 추상 개념을 한 가지 물리 사건으로 바꿨다. 예: 반도체 전망을 폭풍 속 칩 기상도로 바꾼 scene18, 공급망 이동을 생산 라인으로 바꾼 scene29.
2. 전경·중경·배경이 모두 대사에 참여한다. scene04, 05, 10, 18, 29, 42, 43은 캐릭터 뒤에 장식용 배경이 아니라 원인·결과를 설명하는 설비와 소품이 있다.
3. 핵심 관계가 한눈에 읽힌다. scene06의 전체 실적과 두 기업 제외 비교, scene42의 전망 하향, scene43의 매도→매수 전환은 자막을 듣는 동안 이미지의 주제가 바뀌지 않는다.
4. 캐릭터가 설명 대상보다 크지 않다. scene18, 29, 42, 43은 캐릭터가 대상을 가리지 않고 손·시선이 정확히 목표를 향한다.
5. 색이 의미를 나눈다. 경고는 적색, 회복은 녹색/금색, 불확실성은 비·구름·청회색으로 통일되어 있다.
6. 성공의 원인은 특정 Job 분기가 아니라 `장면 로컬 대사 → 가장 적합한 물리 관계 → 필요한 만큼의 소품 → 한 가지 일관된 캐릭터 행동 → 동일 2D 그림 언어` 순서다. 소품 수·의상·위치·패널 수 자체를 전역 고정하지 않는다.

1. **문자 정확성**: 장면 로컬 허용 목록, 한국어/영어 전사, 누락·추가·훼손 검수. scene07/15/35/40 유형이 모두 통과해야 다음 단계로 승격한다.
2. **캐릭터 무결성**: scene08 얼굴, scene11 손, scene02 의상 유형을 각각 소규모 실 API로 검증한다. 얼굴/의상/해부학 세 항목이 모두 통과해야 공통 계약으로 승격한다.
3. **의미 밀도**: scene00/01/20/21/23/45 같은 `number_panel_only`를 물리 인과 장면으로 재설계한다. 숫자만 정확하다는 이유로 합격시키지 않는다.
4. **오염 차단**: 현재 장면에 없는 SILVER/GOLD/가짜 티커/다른 기업이 0개여야 한다.
5. **말풍선**: 명시 승인 필드가 없는 모든 영상에서 0개여야 한다.
6. **참조·계보**: 캐릭터 참조와 화풍 참조가 함께 전송되고 참조 SHA가 manifest 지문에 남아야 한다.
7. 각 범주는 정적 프롬프트 테스트 → 로컬 계약 테스트 → 해당 유형 1장 실 API → 통과 이미지의 프롬프트/참조/QA 결과 기록 순서로 적용한다. 한 범주의 실패 때문에 다른 장면의 화풍이나 구도를 전면 변경하지 않는다.

## 구현·실 API 검증 결과

### 원인에 대한 최종 정정

- 48장에 이미지 모델이 직접 쓴 영문·숫자가 많았다는 사실 자체는 원인이 아니다. 현재 장면 승인 대사에서 가져온 정확한 문자열이면 정상이다.
- 실제 원인은 ① 장면별 허용 문자열 경계가 없었고, ② 프롬프트 생성기가 빈 보조 화면·간판·계기판을 임의 문구로 채웠으며, ③ OCR 미검출을 합격으로 취급했고, ④ 결과 QA가 화면의 모든 문자를 전사하지 않았다는 결합이다.
- 따라서 무문자화가 아니라 `현재 장면 승인 문자열은 정확하게 허용 + 현재 장면에 없는 문자열은 차단 + 금융 수치는 결정론 렌더 + 결과 전체 전사 대조`로 구현했다.
- OCR이 한국어 오탈자를 놓친 것은 결함의 생성 원인이 아니라 검출 실패 원인이다. 생성 원인은 문자열 정확성 계약과 장면 로컬 경계가 없었던 것이다.

### 전역 파이프라인에 반영된 계약

1. `scene.screen_texts`만 해당 장면의 이미지 생성 허용 문자열이 된다. 전체 영상의 사실 목록을 모든 장면에 복제하지 않는다.
2. 승인 비수치 한국어·영어는 이미지 모델이 자연스러운 장면 속 표면에 정확히 한 번 쓸 수 있다.
3. 지수값·등락률 등 금융 수치는 프로젝트 전역 규칙에 따라 이미지 모델에 쓰게 하지 않고 Pillow/FFmpeg 경로로 보낸다. 해당 수치가 현재 승인 내레이션에 존재하는지도 다시 확인한다.
4. 임의 보조 간판·가짜 티커·다른 기업·SILVER/GOLD 같은 장면 외 오염을 금지한다. 정보 표면의 개수·종류·배치는 장면별 계획을 따르고 전역 1개로 제한하지 않는다.
5. 작업 번호를 스타일 지시로 쓰지 않는다. Job52에서 실제로 잘 생성된 승인 장면 이미지들을 전역 참조 라이브러리로 삼고, 현재 장면 의미와 가까운 두 장만 골라 전송해 SHA-256을 지문에 기록한다. 캐릭터는 승인 장면 세 곳의 얼굴 크롭 범위를 추가하되 특정 의상·표정·구도를 모델시트처럼 고정하지 않는다.
6. 장면은 `로컬 승인 대사 → 물리 인과 → 필요한 소품 → 한 캐릭터 행동 → 동일 2D 그림 언어` 순으로 구성한다. 거대한 숫자판·문구판만 있는지 여부도 해당 장면 계획과 함께 판정한다.
7. QA는 운영자가 명시한 상한만 따르며 0 이하는 전체 장면을 뜻한다. 48장 작업은 00~47 전체를 검토한다.

- HTTP 생성이 완료된 실 API 실험은 5건이며 추정 비용은 각 254원, 합계 약 1,270원이다. 이는 시각 승인 건수를 뜻하지 않는다. 503으로 취소된 요청 1건은 ledger상 0원이며 실제 청구액은 공급자 콘솔 대사가 필요하다.
- Job 52 원본 이미지는 덮어쓰지 않았다. 기각된 실험의 요청 프롬프트·참조 SHA·OCR·QA는 실패 원인 증거로만 `real_api_pilot_retry2/manifest.json`에 보존했다.
- 4차 실패 증거는 `contextual_lab_real/`, 5차 콘텐츠 우선 결과는 `content_first_lab_real/`에 보존했다. 5차 생성 뒤 로컬 OCR 실행기가 unavailable이었지만 저장된 PNG를 재과금 없이 멀티모달 QA했고 `text_approved_duplicate`, `scene_composition_plan_mismatch`를 정확히 검출했다.
- 최신 전송 계약은 장면·구도·사물 관계를 텍스트 계약보다 먼저 배치한다. 승인 문구는 장면별 표면 계획을 따르며, 별도 재질 계획이 없으면 기존 불투명 모니터·벽면 보드·기계 계기판·도색/각인 사물 표면에 통합한다. 투명 플로팅 카드·홀로그램은 해당 장면 계획이 재질까지 명시할 때만 허용한다.
- 캐릭터 QA는 큰 흰자, 따뜻한 갈색 홍채, 겹친 흰색 캐치라이트, 눈썹, 둥근 코, 볼 홍조, 충분히 그려진 입이라는 공통 얼굴 구조를 검사한다. 표정·눈 뜬 정도·속눈썹·의상·모자·포즈·크기는 장면별 변화를 허용한다.
- 7차 프리플라이트: `approved_scene_face_surface_preflight/manifest.json`. 실 요청 감사 원장: `approved_scene_face_surface_real/request_ledger.json`. 로컬 원장은 세 ReadTimeout을 각 0원으로 취소 처리했지만, 요청 전송 후 타임아웃이므로 실제 청구 여부는 공급자 콘솔 대사가 필요하다.
