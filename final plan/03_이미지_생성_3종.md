# 03. 이미지 생성 — 한국형 · 정보형 · 기사형 (V5 아키타입 위에 얹기)

> 목표: 스크립트 내용과 일치하는 이미지를, **레퍼런스(경제사냥꾼) 화풍·구도**로.
> **캐릭터는 노란 코인 하나로 전 영상 일관.** 초록 지폐는 레퍼런스일 뿐 우리 영상에 등장 금지.
> 모델: **Nano Banana Pro (Gemini 3 Pro Image)** 단일.

## 0. 먼저 — 사용자가 물어본 것: "일반형/정보형으로 나눌 필요 없이 한국형/기사형만 하면 되나?"

**권장 답: 실질적으로 "한국형"과 "기사형" 2계열로 보되, "정보형(근사 수치·그래프)"은
별도 이미지 모드가 아니라 한국형 안의 하위 표현으로 흡수한다.**

이유(피드백 그대로):
- *"수치 정보형 이미지 → 정확한 수치가 나올 필요 없습니다."*
- *"상승이면 빨간 그래프, 하락이면 파란 그래프. 원형그래프는 삼성전자·하이닉스·그 외
  반도체 보유비중을, 수치는 안 맞아도 표현만 원형으로 이해할 수준."*
- *"이미지에 중요한 건 한국형 이미지."* (예: 홈플러스-하림 인수 → 건물은 한국형 슈퍼마켓 정도)

→ 즉 **"정보형"은 정밀 데이터 이미지가 아니라, 한국형 상황 이미지 안에서 방향성만 보여주는
근사 표현**입니다. **정확한 검증 수치가 꼭 화면에 필요하면**, 그때만 결정론 Pillow 오버레이로
소품 표면 위에 얹습니다(모델이 그리지 않음).

| 계열 | 무엇 | 검증 수치 필요? |
|---|---|---|
| **A. 한국형(상황/은유)** | V5 아키타입 무대 + 노란 코인. 데이터는 근사(빨강↑/파랑↓, 원형=비중) | 대부분 불필요. 필요 시 오버레이 |
| **B. 기사형(캡처)** | 실제 기사/공시 캡처에 밑줄·하이라이트 | 기사 원문이 근거 |

> 코드 레벨의 `scene_type`(general/metric/graph/diagram/text)은 **내부 분류 신호로 유지**해도
> 됩니다. 다만 렌더 결과는 위 A/B 두 계열의 화면으로 수렴시키고, `metric/graph`가
> "정밀 숫자 카드"로 튀지 않게 근사 표현으로 렌더합니다. (이미 `_rebalance_scene_type_distribution`이
> 지표형·다이어그램형 비중을 상한으로 눌러 단조로움을 막고 있음 — 이 로직 유지.)

## 2. 11종 V5 아키타입 (한국형 무대 = 그대로 재사용)

V5에서 만든 씬 아키타입은 **한국형 상황 무대 그 자체**입니다. 새로 만들지 말고 매핑해서 씁니다.

| 아키타입 | 은유 | 대표 대본 상황 |
|---|---|---|
| `port_emergency` | 폭풍우 항구 비상등 | 공급망 차질, 수출 경고 |
| `retail_shock` | 마트 계산대 폭탄 가격 | 물가·관세로 소비자가 상승 |
| `classroom` | 교실 칠판 개념 설명 | 용어·구조 설명 |
| `weather_map` | 기상캐스터 관세/전망 맵 | 전망·확률·지역별 영향 |
| `split_stage` | 무대 좌우 대비 조명 | A vs B 비교(중국 vs 한국 등) |
| `trade_calculator` | 거대 황금 저울 | 밸류에이션·관세 균형 |
| `data_lab` | 홀로그램 데이터 랩 | 지표 종합·대시보드 |

+ 그 외 4종. **아래는 primary-surface 파일럿 결과** — 텍스트를 지정된 물리 소품 1곳에만 묶고,
그 외 소품은 무텍스트로 처리하는 접근(첨부):

![V5 primary-surface 파일럿 3종 비교](assets/our_character/06_v5_primary_surface_pilot_아키타입비교.png)

> 이 파일럿의 핵심 = **"텍스트는 지정 소품 1개에만, 나머지 소품은 글자 없음, 정확한 검증
> 수치는 나중에 결정론 오버레이로."** 이 원칙을 유지하면 배경 글자 깨짐이 크게 줄어듭니다.

## 3. 배경 텍스트 깨짐 억제 규칙 (Nano Banana Pro 대응)

Nano Banana Pro는 한국어 텍스트 렌더링이 강해졌지만, **잡다한 배경 영어 라벨은 여전히
깨지고 값도 틀릴 수 있습니다(Google 공식 경고).** 그래서:

1. 배경/소품 프롬프트에 **`no readable text, no letters, no words, no UI elements`** 유지.
2. 화면에 **꼭 필요한 문자는 "지정된 primary 소품 1곳"에만** (맵/칠판/상자/저울 등).
3. **검증 수치(지수·등락률·금액)는 모델이 아니라 결정론 오버레이(Pillow/matplotlib)**로.
   - `hero_stat_from_chart` → 소품 표면 좌표에 결정론 렌더.
4. 근사 데이터 표현(방향성)은 **모델이 그려도 됨**: 빨강 상승 화살표/파랑 하락 화살표,
   원형그래프(비중 근사). **수치 라벨은 붙이지 않거나 오버레이로.**

---

## 4. 정보형(근사) 표현 규칙 — "수치 안 맞아도 OK, 방향만"

| 표현하려는 것 | 이미지에 넣는 것 | 정확 수치? |
|---|---|---|
| 상승 | **빨간** 상승 그래프/화살표 | ❌ 방향만 |
| 하락 | **파란** 하락 그래프/화살표 | ❌ 방향만 |
| 종목 보유비중(삼성전자/하이닉스/그 외) | **원형그래프**(크기 근사) | ❌ 표현만 이해되면 됨 |
| 특정 검증 수치가 대본 핵심일 때 | 그 값만 **결정론 오버레이**로 소품 위에 | ✅ 오버레이로만 |

- **금지:** 화면에 정밀 숫자 카드를 모델로 생성 / 그래프라며 UI 박스 합성 / 자막 뒤 검은 판.
- 폴백은 flat 카드가 아니라 `DATA_CUTAWAY`. (탐지 실패 시 조용한 flat overlay 금지)

---

## 5. 기사형(캡처) 표현 규칙 — 이번에 추가

- 실제 기사/공시를 **Playwright DOM bounding box**로 캡처(설치 필요 — 미설치 상태).
- 캡처 위에 **밑줄·하이라이트**를 결정론 렌더로 얹음(핵심 문장 강조).
- 근거는 기사 원문 → `source_ref` 추적. **없는 문장·수치 창작 금지.**
- 캐릭터(노란 코인)는 캡처 옆에서 가리키는 포즈로 배치 가능.

---

## 6. 캐릭터 일관성 (노란 코인)

- Nano Banana Pro는 **최대 5인 정체성 유지 / 다중 이미지 합성** 지원 → 노란 코인
  캐릭터 시트를 **레퍼런스 이미지로 항상 첨부**해 전 씬 일관 유지.
- 감정 태그(happy/worried/surprised/pointing/thinking/explaining/neutral)와 포즈만 바꾸고
  **캐릭터 디자인은 고정**(네이비 정장, 코인 얼굴). 채널별 프로필 격리(크로스 블리드 금지).
