# 01. 롱폼 파이프라인 개요 — 키워드 하나 → 썸네일까지 자동

> **키워드만 입력하면** 나머지가 전부 자동으로 흐릅니다. 아래는 각 단계의
> 입력/출력 계약과, **이미 존재하는 것 / 이번에 손댈 것 / 건드리지 말 것**입니다.
> 세부 스펙은 02~05 문서로 분리돼 있습니다.

---

## 전체 흐름

```
[키워드 입력]
   │
   ▼
1. 후보 지표 선정 ─────────► 최고 점수 지표 1개 선택 (키워드 우선순위 절대)
   │
   ▼
2. 스크립트 생성 ─────────► 레퍼런스 스타일 대본 + 3-Round 팩트체크
   │                        (ElevenLabs 분당 처리속도·설정 배속 반영해 길이 산정)
   ▼
3. TTS 생성 ─────────────► v7 음성(선택 IVC), 스크립트 100% 일치, 문자단위 자막 정렬
   │
   ▼
4. 이미지 생성 ──────────► 씬별로 3종(한국형/정보형/기사형) 적절히 배치
   │                        V5 11종 아키타입 + Nano Banana Pro
   ▼
5. 영상 조립 ────────────► FFmpeg 조립 + 초반부 fal.ai(Kling) 모션 인서트
   │
   ▼
6. 썸네일 제작 ──────────► "영상에 실제로 쓰인 이미지"로 레퍼런스 스타일 썸네일 자동 추천
```

각 단계는 **앞 단계의 출력 계약을 그대로 소비**합니다. 특히 2→3→4는 동일한 씬 계보
(`scene_id`, `text_sha256`, `canonical_text_sha256`)를 공유하므로, 한 단계에서
문장을 임의로 자르거나 다시 쓰면 뒤 단계 싱크가 전부 깨집니다.

---

## 1단계 · 후보 지표 선정

| | 내용 |
|---|---|
| **입력** | 사용자 키워드(들) |
| **출력** | 점수 최고 지표 1개 + 카테고리(KOSPI/KOSDAQ/US_STOCKS/…) |
| **이미 존재** | 키워드 파싱(`_selected_keyword_terms`), 별칭 정규화(`normalise_terms`), 근거 뉴스 수집(`_collect_keyword_news`) |
| **절대 규칙** | **키워드 우선순위 절대.** 입력 키워드가 뉴스 빈도·유튜브 지표보다 항상 우선. (과거 `AUTO`가 키워드 무시한 버그 재발 금지) |
| **손댈 것(요청 시)** | YouTube Data API v3 실연동(`RealTrendingVideoAnalyzer` + Redis 캐싱). **Phase 5 웹 UI 전에 완료 필요.** 비용 $0 |

---

## 2단계 · 스크립트 생성 (상세: 02 문서)

| | 내용 |
|---|---|
| **입력** | 선정 지표 + 카테고리 + 목표 분량(분) + 검증 사실 + 선택 음성 ID |
| **출력** | 씬 분할 대본(`sections`) + `verified_facts` + 유튜브 메타데이터 |
| **길이 계약** | `make_length_contract(target_minutes, chars_per_minute, tts_speed, voice_id, model_id)` — **ElevenLabs 분당 처리속도와 설정 배속(0.9x)을 반영**해 목표 글자수 산정 |
| **이미 존재** | 3-Round 팩트체크(`_multi_round_fact_check`), 검증 사실 기반 생성, 흐름 QA(`review_flow`), 키워드 커버리지·단위 검증 |
| **절대 규칙** | LLM은 **텍스트 구조·비유·씬 라벨만** 생성. 수치·날짜·회사명은 `verified_facts`에서만. `%`→`퍼센트`, `포인트`는 절대 변동값 전용 |

---

## 3단계 · TTS 생성 (상세: 02 문서)

| | 내용 |
|---|---|
| **입력** | 승인된 대본 + 선택 음성(`선택음성_v7_question_tone.mp4` 기준) + 목표 초 |
| **출력** | MP3 + **문자 단위 정렬된 자막 청크** + 품질 리포트 |
| **음성** | 선호 IVC, **0.9배속, 안정성 0.25**, v7 질문 억양·미세 높낮이 유지, 문장 사이 **70ms 미세 호흡만** |
| **자막** | 대본을 억지로 줄바꿈하지 않고, **최종 TTS 문자 타임스탬프 기준 15~20자 의미 단위**로 분절·정렬 |
| **하드 게이트** | 스크립트 100% 일치(텍스트 계약 SHA256), CER 게이트, 문자 정렬 실패 시 조립 금지(검토로 회송) |
| **절대 규칙** | ElevenLabs 실패해도 **성우를 몰래 gTTS로 바꾸지 않음** — 게이트에 잡 남김 |

---

## 4단계 · 이미지 생성 (상세: 03 문서)

| | 내용 |
|---|---|
| **입력** | 씬(`sections`) + `verified_facts` + 아트 디렉션 |
| **출력** | 씬별 이미지(노란 코인 캐릭터 일관 유지) |
| **3종 이미지** | **한국형(상황/은유)** · **정보형(근사 수치/그래프)** · **기사형(캡처+밑줄/하이라이트)** |
| **이미 존재** | V5 walking skeleton, **11종 아키타입**, `prompt_builder.py`, `korean_overlay.py`, 씬 분류·리밸런싱 |
| **모델** | Nano Banana Pro(Gemini 3 Pro Image) 단일 |
| **절대 규칙** | **말풍선·수치 카드·검은 배경 박스·엉망 UI 박스 절대 금지.** 검증 수치는 결정론 오버레이로만. 한국형 화풍이 최우선 |

---

## 5단계 · 영상 조립 + fal (상세: 04 문서)

| | 내용 |
|---|---|
| **입력** | 이미지 씬들 + TTS MP3 + 자막 청크 |
| **fal 활용 범위** | **10분 이상 영상 → 약 1분**, **5분 내외(그 미만) → 45초 이내** (인트로 구간만) |
| **이미 존재** | FFmpeg 조립, Kling v2.6 Pro via fal.ai, `만족한_fal_인트로_walking.mp4` 기준 모션 |
| **절대 규칙** | fal은 **인트로에만**. 본문은 이미지. 예산 상한(₩40,000/₩80,000) 프리플라이트로 사전 검사 |

---

## 6단계 · 썸네일 제작 (상세: 05 문서)

| | 내용 |
|---|---|
| **입력** | **영상에 실제로 쓰인 이미지** + `verified_facts` |
| **출력** | 레퍼런스 스타일 썸네일 후보(자동 추천) |
| **이미 존재** | `_build_thumbnail_brief`, thumbnail v2 계약(`chart_warning`/`article_evidence` 템플릿), 내러티브 플랜 |
| **절대 규칙** | 배지/수치는 **`source_ref` 있는 검증값만**. 없으면 배지 없이. 가짜 그럴듯한 수치 금지 |

---

## 단계 간 "동일 계보" 계약 (싱크가 깨지지 않게)

```
스크립트 sections ──(scene_id, text_sha256)──► TTS 자막 청크
        │                                          │
        └───────(canonical_text_sha256)────────────┘
                          │
                          ▼
              이미지 씬 / 조립 타임라인 / 썸네일 source_scene_ids
```

- **한 곳에서 문장을 바꾸면** 반드시 이 계보 전체가 함께 갱신돼야 합니다.
- 대본에서만 문단을 지우고 씬은 그대로 두는 식의 "한쪽만 수정"은 금지
  (코드 주석에도 명시됨: *"장면은 이후 이미지와 타이밍의 기준"*).
