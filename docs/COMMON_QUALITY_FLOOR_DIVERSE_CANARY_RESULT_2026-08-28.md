## 1. 결론

서로 다른 연구실·시장 관제실·극장형 장면을 장면당 1회씩 순차 생성했다. 세 요청 모두 HTTP 200이었고 이미지도 정상 반환됐지만, **세 장 모두 운영 승인에서 제외한다.**

이번 실증은 “한 공통 프롬프트로 모든 장면을 같은 표정·의상·배경으로 만들기”가 해법이 아님을 다시 확인했다. 동일하게 적용할 것은 연출 결과가 아니라 다음의 **공통 합격 하한선**이다.

- 동전 캐릭터 정체성과 정상 해부학
- Job52 계열 2D 잉크·셀 셰이딩 화풍
- 승인 대본 장면에 맞는 표정·의상·행동·배경
- 승인 문자열의 정확성·횟수·물리 표면 결합
- 소품과 행동만 보아도 읽히는 경제 인과

표정·의상·배경은 승인 대본에 따라 달라져야 한다. 어떤 장면은 얼굴, 다른 장면은 텍스트가 실패할 수 있다는 사실은 공통 구조가 없다는 뜻이 아니라, **확률적 생성 결과를 같은 다축 게이트로 검사해 실패한 축만 표적 수정해야 한다는 뜻**이다.

### 1.1 2차 원본 확대 판정 정정

최초 보고 뒤 사용자가 원본 글자와 얼굴을 다시 판독했고, 원장·manifest·디스크 SHA-256과 원본 픽셀을 재대조했다. 다음 두 서술을 정정한다.

- scene07의 “다리가 지나치게 길다”는 판정은 철회한다. 이미지 하단에서 발이 잘려 전체 길이를 확정할 수 없고, 보이는 비례만으로는 긴 인간형 다리 계약 위반을 증명할 수 없다. 캐릭터 해부학과 화풍은 이전 scene07 canary보다 개선됐다.
- scene28은 정확한 `대형주` 3회가 아니다. 왼쪽과 가운데는 `대형주수`, 오른쪽만 `대형주`다. 따라서 **승인 문구 1회 + 접미 이탈자 2회 + 세 표면 중복**으로 판정한다.

scene07의 얼굴 판정은 유지한다. 확대 이미지에서 보이는 흰색은 검은 타원형 눈 안의 작은 catchlight다. 얼굴 v2가 요구하는 갈색 홍채 바깥의 별도 흰자(sclera)는 보이지 않는다. 다만 최초 문구가 이 둘을 구분하지 않아 “흰색이 전혀 없다”는 뜻으로 읽힐 수 있었으므로, 아래에서는 더 정확한 표현으로 바꾼다.

공통 실행 순서는 다음과 같았다.

### 3.1 scene07 — 반도체 데이터 연구실

- 내레이션 SHA-256: `143e208a9e08b8b0cd335b3084dd9bf88af17b6ac68576af0ae206ed147a6d23`
- 참조:
  - `channel_character_face_range_v2.png` — `7e7981e3…8e40e`
  - `channel_character_face_scene05_v1.png` — `7b6c97c2…fae6e2`
  - `channel_style_semiconductor_production_scene_v1.png` — `17ae053e…74179d`
- attempt: `97931aa419cf4a7ea5fad1016f6a071d`
- 파일 동일성: attempt 원장, manifest `raw_sha256`, 디스크 파일이 모두 `b230878c7b685b18c118f47a9ba84deda554d0c18dfe9b34464475180861d493`로 일치한다. 다른 canary 이미지가 섞이지 않았다.
- 결과: 캐릭터와 연구실 화풍·해부학은 이전 canary보다 개선됐다. 눈은 검은 타원형 fill과 흰 catchlight를 갖지만, v2의 별도 흰자와 갈색 홍채 구조는 없어 얼굴 계약은 아직 통과하지 못한다. 다리 길이 위반 판정은 철회한다. 두 용기는 존재하나 “두 기업 제외 후 시장 합계”라는 의미는 라벨/행동 없이 명확하지 않다.
- 결정론 후처리: 빈 모니터가 커 보이지만 검출기가 요구하는 명확한 물리 프레임을 확보하지 못해 `ValueError: 물리 표면에 충분히 분명한 프레임 선이 없습니다.`로 fail-closed 됐다. 승인 문자열은 합성되지 않았다.

### 3.2 scene28 — 시장 위험 관제실

- 참조:
  - `channel_character_face_range_v2.png` — `7e7981e3…8e40e`
  - `channel_style_job52_briefing.png` — `b31b98d6…15c46a`
  - `channel_style_job52_market_flow.png` — `c9e821d5…03a74`
- attempt: `129ddb6efbdd4b4fadb8952d5781c565`
- 결과: 장면 역할·의상·배경 밀도는 비교적 잘 맞았다. 그러나 왼쪽·가운데 모니터에는 비승인 접미 변형 `대형주수`가 각각 1회, 오른쪽 모니터에만 승인 문구 `대형주`가 1회 나타났다. 정확 문구 횟수뿐 아니라 의사문자/이탈자 실패다.
- 중요한 검출 공백: Tesseract 측정은 `대형주`를 **0회**로 기록했다. PSM 6/11/12 원자료는 `Ss`, `oo`, `02`, `매지`, `부` 같은 노이즈만 반환했고 `대형주`나 `대형주수` 어느 쪽도 검증 함수에 전달하지 못했다. 따라서 이번 실패는 정확대조 함수의 substring 회귀가 아니라 **그 앞단 OCR 재현율 실패**다.
- 경계 계약 재확인: OCR이 `대형주수`를 실제 문자열로 반환하면 `_find_exact_token_sequence`와 strict generated-text gate는 이를 `대형주` 적중으로 세지 않고 비승인 문자로 거절한다. 실제 canary 문자열을 회귀 테스트에 추가했다.

- 참조:
  - `channel_character_face_range_v2.png` — `7e7981e3…8e40e`

## 4. 참조 이미지가 실제로 한 일과 한계

세 요청 모두 첫 참조로 얼굴 v2가 실제 전송됐고, 뒤의 두 장은 프롬프트 문맥으로 선택됐다. 참조 누락이 원인은 아니다. 다만 현재 화풍 참조는 순수 스타일 시트가 아니라 Job52 완성 장면이라 다음 신호를 동시에 갖는다.

- 좋은 신호: 굵은 잉크선, 셀 셰이딩, 경제 소품 밀도, 장면별 의상 다양성
- 위험 신호: 장면에 박힌 기존 문자·수치, 서로 다른 신체 비례, 특정 구도·소품

따라서 참조가 전달됐다는 사실만으로 얼굴·해부학·텍스트가 보장되지 않는다. 생성 프롬프트와 후단 품질 게이트가 각각 참조의 좋은 속성만 요구하고 위험 신호를 거절해야 한다. 장기적으로는 얼굴·전신 비례·배경 화풍 역할을 분리한 오염 없는 참조 세트가 필요하다.

## 5. 실증을 통해 공통 운영 경로에 반영한 수정

### 5.1 캐릭터 계약 교정

기존의 `no separate human torso`는 Job52 승인 장면의 정장·코트 표현까지 잘못 거절할 수 있었다. 이를 다음 계약으로 교체했다.

- 동전 원판은 항상 지배적인 머리·상체 정체성
- 코트·정장·가운이 동전 테두리 아래로 적당히 감싸는 것은 허용
- 좁은 목으로 분리된 독립 인간 몸통은 금지
- 보이는 다리는 각각 동전 지름의 약 1/2 이하인 짧고 통통한 비례
- 긴 인간형 다리, 추가·융합·분리된 팔다리는 금지

이 계약은 `character_integrity_contract.py`, `scene_director.py`, 실제 prompt builder, Gemini reference contract, 최종 visual QA에 공통 반영됐다. 캐릭터 계약 버전은 `v6`, 장면 품질 계약은 `v2`, visual QA 정책은 `17`이다.

### 5.2 승인 문구 횟수

기존 멀티모달 QA는 명시적 strict 플래그가 없으면 승인 문구 2회까지 허용했다. 이제 surface plan이 `max_occurrences`를 명시하면 그 값 자체가 엄격한 상한이 된다. 다만 scene28의 직접 원인은 정확 문구 3회가 아니라 `대형주수` 2회와 `대형주` 1회다. 정확 횟수 상한과 별도로, 멀티모달 원본 검수는 접미 이탈자를 `unexpected_or_malformed_texts`로 거절해야 한다.

### 5.3 캐시·재생성

프롬프트/검수 계약 변경 후 과거 성공 이미지를 새 정책 결과처럼 재사용하지 않도록 이미지 계보 fingerprint를 `9→10`으로 올렸다. 이 변경은 전체 생성과 단일 장면 재생성의 공통 worker 경로에 적용된다.

## 8. 다음 구현 순서

1. `semantic_object_id`와 `surface_id`로 승인 문구를 실제 소품별 물리 표면에 연결한다. scene07처럼 네 문구를 모두 `main` 하나에 몰아넣지 않는다.
2. generated short label도 `surface_id`가 없으면 화면 하단 자막형 배치를 금지하고 fail-closed 한다.
3. OCR은 빠른 1차 게이트로 유지하되, 원본 해상도 멀티모달 검수의 횟수 판정과 사용자 실물 검토를 함께 사용한다.
4. 얼굴·전신 비례·배경 화풍 참조를 역할별로 분리하고, 문자·수치가 들어 있는 완성 장면 참조의 오염도를 낮춘다.
5. 수정 후 서로 다른 2~3개 주제 canary를 다시 실행한다. 통과한 정지 이미지가 생기기 전에는 Fal로 넘어가지 않는다.
