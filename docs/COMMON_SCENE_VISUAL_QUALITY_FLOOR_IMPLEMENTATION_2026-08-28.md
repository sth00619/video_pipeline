# 공통 장면 시각 품질 하한선 운영 반영

- 작성일: 2026-08-28 KST
- 범위: 이미지 생성 버튼이 타는 공통 생성·재개·단일 장면 재생성 경로
- 유료 API 호출: 0회
- 실제 영상/TTS/Fal/조립: 실행하지 않음
- 결론: 같은 연출을 반복하는 방식이 아니라, 서로 다른 연출이 같은 합격 하한선을 통과하도록 운영 계약을 추가했다.

## 1. 사용자 문제 제기에 대한 비판적 결론

“같은 코드면 모든 장면의 얼굴·의상·텍스트 품질도 처음부터 같아야 한다”는 기대는 생성 모델의 확률성 때문에 그대로 보장할 수 없다. 같은 모델·코드·참조·프롬프트 구조를 써도 장면의 소품 수, 인물 크기, 표정, 카메라, 배경 복잡도가 달라지면 서로 다른 축에서 실패할 수 있다.

그러나 이전 구조에는 실제 공통 결함이 있었다.

1. 생성 프롬프트는 얼굴의 홍채·흰자·반사광을 상세히 요구했지만, 최종 시각 QA는 다른 종 또는 거의 무표정한 이모지 수준만 강제 거절했다.
2. 장면별 의상이 있어도 `wardrobe_strict=true`가 아니면 역할과 맞지 않는 의상을 승인할 수 있었다.
3. 결정론 문구용 표면의 6~14% 크기 지시는 재시도 프롬프트에만 있었고 최초 생성에는 상한이 없었다. 따라서 scene07 canary 같은 거대한 빈 모니터가 나올 수 있었다.
4. 시각 QA가 `retry_recommended=true`를 반환해도 명시 실패 범주가 비어 있으면 이미지 워커가 승인했다.
5. 최신 캐릭터 계약은 짧고 통통한 팔다리를 요구하지만 일부 공통 프롬프트는 아직 `thin dark legs`, `exact face`, `large blank board`, `RIGHT half`를 요구했다.

따라서 해결 목표는 첫 생성의 무결점 보장이 아니라 다음 구조다.

```text
공통 품질 하한선(모든 장면 동일)
  + 대본별 연출 변수(장면마다 다름)
  + 생성 후 다축 fail-closed 검수
  + 실패한 축만 표적 재생성
= 다양하지만 품질 기준은 일관된 운영 이미지
```

## 2. 공통 품질 하한선과 장면 변수의 분리

새 모듈 `app/utils/scene_visual_quality_contract.py`는 모든 장면에 다음 공통 하한선을 적용한다.

- 하나의 둥근 동전 원판이 머리와 몸통을 이루는 캐릭터 실루엣과 정상 해부학
- 화면 속 크기에 맞게 의도적으로 완성된 얼굴 표현
- 해당 장면 역할과 맞는 표정·행동·의상
- 굵기 변화가 있는 잉크선과 셀 셰이딩을 쓰는 2D 경제 에디토리얼 코믹 화풍 범위
- 승인 대본의 경제 인과를 소품과 행동으로 읽을 수 있는 장면
- 텍스트 표면 밖의 정보 밀도와 배경 깊이
- 장면 승인 문구만 허용하고 금융 수치는 결정론 렌더링하는 기존 계약

반면 다음은 공통 고정값이 아니다.

- 의상, 모자, 표정, 눈의 개폐, 입 모양
- 행동, 카메라, 캐릭터 크기와 위치
- 연구실·항구·교실·시장·공장 등 배경
- 장면 고유 소품과 색조

예를 들어 반도체 장면은 실험복·고글·호기심 표정으로, 항구 급락 장면은 현장 기자 외투·긴박한 표정으로 생성된다. 두 장면은 외형이 달라도 동일한 `scene-visual-quality-floor-v1`을 통과해야 한다.

## 3. 텍스트·수치 표면과 정보 밀도

승인 문구 수에 따라 단일 최대 표면 예산을 다음처럼 제한했다.

| 승인 문구 수 | 단일 최대 표면 비율 | 공통 조건 |
|---:|---:|---|
| 0~1 | 16% | 표면 밖 경제 서사 영역 최소 60% |
| 2~4 | 22% | 동일 |
| 5 이상 | 24% | 동일 |

이는 글자를 없애는 정책이 아니다. 짧은 승인 문구도, Pillow가 쓰는 결정론 문구도 장면을 압도하는 거대 보드로 몰리지 않게 하는 공간 예산이다. 금융 수치 자체는 계속 Gemini에 주지 않고 Pillow/FFmpeg가 쓴다.

최초 생성 프롬프트에도 다음 계약이 들어간다.

- 표면은 장면 안의 실제 소품이며 종속적이어야 한다.
- 빈 화면을 크게 만드는 대신 나머지 영역에 대본 관련 소품·기계·인과 행동·전경/중경/배경을 유지한다.
- 공통 계약은 고정 의상·고정 표정·고정 배경 템플릿이 아님을 명시한다.

기존 공통 `prompt_builder.py`의 `exact face`, `thin dark legs`, `large blank board`, `RIGHT half` 지시도 범위형 얼굴·짧은 팔다리·최대 약 22%의 종속 표면으로 정렬했다.

## 4. 최종 QA에서 새로 강제하는 항목

시각 QA 정책을 v15에서 v16으로 올리고, 이전 캐시를 재사용하지 않는다. 모든 새/재개 장면은 같은 최종 프레임에서 다음 항목을 판정한다.

| 판정 | 실패 범주 | 의미 |
|---|---|---|
| 얼굴 구성 품질 | `character_face_quality` | 다른 종뿐 아니라 우연히 단순해진 얼굴도 차단. 의도된 감은 눈/놀란 눈은 허용 |
| 표정·행동 역할 | `character_expression_role` | 대본이 요구한 감정·행동과 맞는지 |
| 의상 역할 | `character_wardrobe` | 픽셀 동일 의상이 아니라 장소·역할 적합성 |
| 화풍 범위 | `style_family_mismatch` | 3D/제너릭 AI 화풍뿐 아니라 채널 2D 범위 이탈 |
| 정보 밀도 | `scene_information_density` | 거대 빈 화면·빈 스튜디오·장식뿐인 배경 차단 |
| 표면 크기 | `deterministic_surface_oversized` | 승인 문구 표면이 공간 예산을 넘는지 |
| 장면 인과 | `scene_semantic_underexplained` | 그림만 보고 대본의 핵심 관계가 읽히는지 |

점수 미달 또는 `decision=review`인데 모델이 실패 범주를 빠뜨린 경우도 `visual_quality_floor`로 승격해 조용히 승인하지 않는다.

## 5. 표적 재생성 원칙

실패 장면을 모두 같은 모습으로 다시 만드는 대신 실패 축만 고친다.

- 얼굴 실패: 장면 고유 감정은 보존하고 얼굴 완성도만 수정
- 표정 실패: 장면의 감정·행동 역할만 수정하며 기본 진행자 표정으로 통일하지 않음
- 의상 실패: 장면 역할에 맞게 수정하며 정장·경찰복·실험복을 전역 고정하지 않음
- 표면 과대: 표면만 축소하고 확보된 공간을 대본 관련 소품과 인과 행동으로 복원
- 정보 밀도 실패: 임의 글자·숫자를 늘리지 않고 실제 경제 소품과 깊이를 복원
- 화풍 실패: 장소·의상·감정은 보존하고 2D 에디토리얼 화풍만 복구

재시도 프롬프트는 기존의 “실패로 지목되지 않은 구도·소품·팔레트·정보 밀도를 보존” 계약과 결합된다.

## 6. 실제 생성 버튼 경로 연결

공통 경로는 다음과 같다.

```text
UI 영상/이미지 생성 요청
→ Spring FastApiClient
→ ImagesWorker 장면 메타데이터
→ 승인 대본 + SceneDirector 장면별 의상/표정/행동
→ build_scene_text_contract
→ build_scene_visual_quality_contract (신규 공통 경계)
→ _bounded_text_generation_prompt
→ select_contextual_reference_paths
→ Gemini 실제 요청
→ OCR/결정론 Pillow 오버레이
→ visual QA v16 공통 다축 게이트
→ 실패 축만 재생성 또는 보류
→ 승인 이미지에만 Fal 안전성 평가
```

`_bounded_text_generation_prompt`는 전체 병렬 생성, 단일 장면 재생성, 문자/시각 실패 재시도, 과거 Job 재개 원본 재검증 경로에서 공통으로 호출된다. `IMAGE_LINEAGE_FINGERPRINT_VERSION`은 8로 올렸다. 과거 v7 산출물은 무조건 폐기하지 않고 OCR·결정론 오버레이·v16 시각 QA를 다시 통과해야만 승격된다. 과거 유료 canary의 고정 해시는 새 프롬프트로 재생되지 않고 드리프트로 거절되어 증거 계보를 보존한다.

## 7. 현재 참조 이미지와 역할

기본 보존 자산은 다음 9장이다.

- 얼굴 범위: `channel_character_face_range_v2.png`
- 고글 얼굴 보조: `channel_character_face_scene05_v1.png`
- Job52 화풍 범위: data_lab, briefing, risk_map, semiconductor, market_flow 5장
- 반도체 화풍 보조: growth, production 2장

모든 9장을 한 요청에 넣지 않는다. 실제 프롬프트 문맥으로 data_lab/semiconductor/risk_weather/market_flow/briefing 그룹을 선택하고, 얼굴 기준 1~2장과 문맥상 가까운 화풍 장면을 합쳐 최대 3장만 보낸다. 이 방식은 Job52 한 장의 표정·의상·구도를 복제하지 않고 허용 화풍 범위를 전달하기 위한 것이다.

## 9. 세 가지 큰 목표와 현재 상태

진행률은 코드 줄 수가 아니라 다양한 신규 주제의 실제 완성 영상으로 입증됐는지를 포함한 보수적 수치다.

### 목표 1 — YouTube 근거·5분 분량·TTS·자막·이미지 의미 동기화: 약 68%, 이번 변경으로 수치 유지

- 기존 반영: YouTube/23개 언론사/검증 사실 계보, Claude 4.6, 실제 CPM 기반 5분 길이, 승인 대본 SSOT, TTS 청크와 자막 경계.
- 이번 연결: 승인 대본에서 SceneDirector가 뽑은 장면별 행동·표정·의상이 이미지 품질 계약의 장면 변수가 된다. `scene_causal_story_match`가 이미지가 해당 청크를 실제로 설명하는지 검사한다.
- 수치를 올리지 않은 이유: 이번에는 신규 5분 영상의 SCRIPT→TTS→IMAGES 실 E2E를 실행하지 않았다.

### 목표 2 — Fal의 자연스러운 국소 모션: 약 38%, 이번 변경으로 수치 유지

- 기존 반영: 문자·수치·그래프 잠금, 카메라/가장자리 지글링 차단, fail-closed.
- 이번 연결: 얼굴·의상·화풍·정보 밀도·장면 인과 중 하나라도 실패한 정지 이미지는 Fal 후보가 되기 전에 거절된다.
- 수치를 올리지 않은 이유: 승인 정지 이미지로 캐릭터 팔·컨베이어·조명 같은 국소 모션을 실 API 검증하지 않았다.

### 목표 3 — 이미지 의미·화풍·텍스트·수치·캐릭터 정확성: 실증 약 68%, 코드 계약 진전

- 이번 반영: 생성과 승인 사이에 없던 공통 다축 품질 하한선, 표면 공간 예산, 역할형 의상/표정 검수, 정보 밀도·장면 인과 검수를 운영 경로에 추가했다.
- 진행률을 즉시 올리지 않은 이유: 오프라인 계약과 회귀는 통과했지만 서로 다른 신규 주제의 실제 Gemini 결과가 이 하한선을 반복 통과했다는 증거는 아직 없다.
- 다음 실증: 서로 다른 역할의 소규모 canary를 생성해 실물 이미지와 자동 판정을 함께 제출하고 사용자 육안 확인을 받는다.

의존 순서는 그대로다.

```text
목표 1의 승인 대본/TTS/자막 청크
→ 목표 3의 정확하고 의미 있는 정지 이미지
→ 목표 2의 안전한 국소 Fal 모션
→ 영상 조립
```

## 11. 아직 완료가 아닌 것

1. 자동 시각 QA는 확률적 판독이므로 유료 canary 실물의 사용자 육안 확인을 대체하지 않는다.
2. 표면별 `semantic_object_id`/`surface_id` 바인딩은 별도 트랙이다. 이번 작업은 기존 surface plan을 바꾸지 않았다.
3. scene15 의사문자와 여러 실제 배경에서의 OCR 재현율은 계속 측정해야 한다.
4. 16/22/24% 표면 예산은 현재 안전 계약의 시작값이다. 다양한 실제 장면에서 글자 가독성과 정보 밀도를 함께 측정해 조정하되, 특정 scene 예외로 조정하지 않는다.
5. 목표 3의 실증 진행률은 실제 다주제 canary가 통과하기 전에는 올리지 않는다.
