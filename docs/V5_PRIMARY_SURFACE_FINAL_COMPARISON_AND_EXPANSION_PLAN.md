## 재현 가능한 보정 방법론

이번 파일럿에서 검증된 방법은 다음 한 줄로 요약된다.

> **primary 표면을 실제 물체의 위치까지 구체화하고, 모델이 대신 고를 법한 그럴듯한 소품을 명시적으로 금지하며, primary 외 모든 소품을 개별적으로 비문자 처리한다.**

| 단계 | 계약 | 검증된 사례 |
|---|---|---|
| 1. 정확한 물체 지정 | "앞면" 같은 포괄어 대신 위치·형상·연결 관계까지 지정한다. | `trade_calculator`: "저울 중앙 기둥 바로 아래의 넓은 각인 받침" |
| 2. 대체물 금지 | 별도 명패·독립 화면·떠 있는 알림 같은 대체 후보를 archetype별로 금지한다. | 저울 받침 대신 독립 명패로 새던 문제를 해결 |
| 3. 비-primary 전수 열거 | 화면·게이지·명패뿐 아니라 테마상 의미 있는 상자·우산 등도 비문자 목록에 넣는다. | `risk_control_room`: shipping crate의 `GLOBAL TRADE` 누출을 제거 |
| 4. primary 의무화 | primary에는 2~3개 짧은 장식 영문/표본 수치를 **반드시** 넣도록 한다. | `data_lab` 지도에 `GLOBAL DATAFLOW` 등으로 확인 |
| 5. 사실값 분리 | AI의 문자·숫자는 재질/원근 테스트용 장식이며, 검증 값은 같은 표면 좌표에 Pillow/FFmpeg로 합성한다. | 금융 수치의 출처·정확도를 이미지 모델에 맡기지 않음 |

## 확장 순서와 비용 발생 전 준비 절차

추천 순서는 **weather_map → classroom → port_emergency → retail_shock**이다. 앞의 둘은 지도 벽/교수 벽처럼 넓고 고정된 단일 표면이 있어 data_lab의 성공 조건과 가장 가깝다. `retail_shock`은 가격표·포장·별도 POS 패널이라는 대체 후보가 가장 많으므로 마지막에 단독 검증하는 편이 안전하다.

1. 위 표에서 각 archetype의 primary 문장을 위치까지 확정하고, 대체 위험에 나온 소품을 개별 금지 목록으로 확정한다.
2. 프롬프트 문자열만 생성해 `primary 1개`와 `비-primary 전수 비문자`가 동시에 들어가는지 비용 없이 검토한다.
3. 사용자 승인 뒤 **한 archetype당 1장, 자동 재시도 없음**으로 호출한다. 실패/503이면 즉시 중단하고 원장·API 로그를 남긴다.
4. 사람 육안으로 `오염 없음 / primary 집중 / 나머지 비문자` 3가지를 확인한다. 한 항목이라도 실패하면 그 archetype만 다시 보정한다.
5. 성공 호출은 콘솔 실비와 원장을 대조한 후에만 다음 archetype으로 진행한다.
