## 1. 결론

두 결함을 서로 다른 원인 계층에서 분리해 수정했다.

- A — scene28의 `대형주수`: 정확대조 게이트의 문제가 아니라, 축소 전체 프레임 OCR이 물리적으로 분리된 여러 모니터의 작은 문자를 읽지 못한 재현율 문제였다. 공통 strict generated-text 경로에 원본 해상도·표면별·원근 보정 재판독을 추가했다. 실제 scene28 원본에서 `대형주`와 `대형주수`를 읽었고, 승인되지 않은 `대형주수` 때문에 최종 판정은 올바르게 실패한다.
- B — scene07의 눈: 얼굴 참조 누락은 아니었다. 전송된 얼굴 v2와 scene05 고글 참조 모두 흰자와 갈색 홍채를 분명히 포함했다. 기존 프롬프트의 `pupil or iris` 표현과 자동 QA가 흰 캐치라이트와 흰자 영역을 구조적으로 분리하지 못한 계약 공백이었다. 공통 Gemini 참조 계약, 캐릭터 계약, 시각 QA를 공막→홍채→동공→캐치라이트 네 영역으로 명시하고 과거 캐시를 무효화했다.

A는 실제 보존 이미지에서 오프라인 결과까지 확인했다. B는 프롬프트·참조·QA 계약이 공통 경로에 반영됐지만, 새 Gemini 생성 결과에서 개선됐다고 아직 주장하지 않는다. 공급자의 확률적 계약 미준수 가능성은 다음 승인된 실 API canary로 확인해야 한다.

scene42는 건드리지 않았고, TTS·Fal/Kling·MP4 조립·썸네일도 실행하지 않았다.

## 2. A — 다중 물리 표면 OCR 재현율

### 2.1 원인 분리

scene28 원본은 여러 모니터가 기울어진 상태로 작게 배치되어 있다. 기존 960px 전체 프레임 Tesseract 결과에는 승인 문구와 접미 이탈자가 모두 없었다. 따라서 정확대조 로직은 비교할 입력 자체를 받지 못했다.

기존 scene35 `전망치` 국소 판독은 미리 알려진 단일 타일에 강했다. scene28처럼 표면이 여러 개이고 좌표가 장면마다 달라지는 경우에는 그대로 일반화할 수 없었다. scene28 좌표를 하드코딩하지 않고 다음 공통 규칙을 추가했다.

1. strict generated-text 레인에서만 표면 재현율 보강을 켠다.
2. 원본 해상도에서 밝고 불투명한 사각 물리 표면 후보를 OpenCV로 찾는다.
3. 각 사각형의 회전·원근을 보정하고, 상대 비율로 정의한 세 종류의 상단 문자 영역을 판독한다.
4. 한국어 OCR PSM 6/11 결과 중 승인 문구와 정확 일치하거나 접두·접미·절단 관계에 있는 문자열만 증거로 넘긴다.
5. OCR이 읽지 못한 문자열을 추측하거나 승인 문구로 보정하지 않는다.

이 경로는 `ImagesWorker`의 공통 strict generated-text 검증에서 호출된다. 즉 다음 영상 생성 버튼 실행의 모든 장면 중 같은 계약을 사용하는 장면에 적용되며 scene28 전용 분기가 아니다.

### 2.2 실제 scene28 판정

실제 원본 `artifacts/common_quality_floor_canary_20260828/scene_28_raw.png`에서 다음을 얻었다.

- 검출 문자열: `대형주`, `대형주수`
- 승인 문자열: `대형주`
- 비승인 문자열: `대형주수`
- 최종 판정: 실패

가운데 일부 표면에서 OCR이 `형주수`처럼 일부만 읽은 경우도 있었다. 시스템은 이를 승인 문자열로 복원하지 않는다. 다른 표면에서 실제 `대형주수`가 완전하게 읽힌 경우만 비승인 근거로 사용했다.

원문 증거: `evidence/wo_img01_h/scene28-surface-recall.json`

### 2.3 적용 범위와 한계

이번 검출기는 밝은 사각형 물리 표면과 승인 문구 기반 strict 레인에 대한 공통 보강이다. 모든 색·질감·곡면·가려진 표면의 텍스트를 완전하게 검출한다는 통계적 근거는 없다. 검출 실패나 애매한 판독은 계속 fail-closed 및 사용자 검토 대상으로 남긴다.

### 3.3 공통 계약 수정

다음 네 영역을 순서와 포함 관계가 명확한 단일 계약으로 바꿨다.

1. 눈 바깥쪽을 둘러싸는 흰 공막 영역
2. 공막 안쪽의 따뜻한 갈색 홍채
3. 홍채 안쪽의 더 어두운 동공
4. 홍채 또는 동공 안쪽의 흰 캐치라이트

`검은 타원 안의 흰 점`은 공막으로 인정하지 않으며, 고글·안경을 착용해도 열린 눈의 네 영역을 지우면 안 된다고 명시했다. 의도적으로 감은 눈은 이 계약의 열린 눈 판정에서 제외한다.

반영 위치:

- Gemini 최종 참조 계약: `app/v5/providers/gemini_provider.py`
- 공통 캐릭터 무결성 계약: `app/utils/character_integrity_contract.py`
- 생성 후 공통 시각 QA: `app/utils/visual_qa.py`
- 이미지 계보 fingerprint: `app/workers/images_worker.py`의 10→11 상승

시각 QA 응답에 `separate_sclera_region_visible`, `warm_brown_iris_region_visible`를 추가했고, 각각 거짓이면 `character_sclera_structure`, `character_warm_brown_iris`로 실패한다. 과거 이미지가 새 계약 아래에서 캐시 재사용되지 않도록 fingerprint를 올렸다.

### 3.4 남은 불확실성

참조는 정확했고 프롬프트에도 `visible white sclera` 계열 지시는 있었으므로, 공급자가 한 표본에서 지시를 확률적으로 놓친 영향도 배제할 수 없다. 이번 수정은 애매한 문구와 QA 공백을 제거했지만 새 유료 생성 없이 실제 준수율을 측정할 수는 없다.

## 5. 세 가지 큰 목표와의 연결

### 목표 1 — 시간 보정·자막 청크·TTS 싱크

이번 수정은 승인 내레이션, TTS 입력, 자막 청크를 바꾸지 않았다. 목표 1의 단일 기준을 보존한 채 이미지 검증만 보강했다. 따라서 문장 길이·음성·자막 타이밍에 새로운 변동을 만들지 않는다.

### 목표 2 — Fal 동작과 영상 조립

텍스트 오탈자나 눈 구조 실패 이미지는 Fal 입력으로 보내기 전에 차단되어야 한다. 이번 수정은 그 선행 이미지 품질 게이트를 강화했다. Fal 자체는 실행·수정하지 않았으며, 텍스트·수치 표면에는 모션을 적용하지 않는 기존 fail-closed 원칙을 유지한다.

### 목표 3 — 스크립트 의미·정확한 텍스트·일관된 이미지

- Job52 scene28 계열의 `대형주수` 같은 접미 이탈자가 OCR 미검출로 통과할 위험을 낮췄다.
- Job52 scene05처럼 흰자·갈색 홍채·동공·캐치라이트가 분리된 얼굴을 공통 생성·검증 계약으로 만들었다.
- 특정 job의 좌표나 단어를 고치는 방식이 아니라, strict 텍스트 표면과 열린 눈을 가진 모든 미래 장면에 적용되는 공통 운영 계약으로 반영했다.

다만 목표 3 완료를 주장하지 않는다. 다른 표면 유형의 OCR 재현율과, 새 눈 계약 아래 실제 Gemini 생성 성공률은 다주제 실 API 표본으로 계속 확인해야 한다.
