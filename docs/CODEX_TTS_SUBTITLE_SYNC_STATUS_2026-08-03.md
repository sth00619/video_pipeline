## 이번에 확인된 원인

- 과거 8월 파일럿의 전체 `script`와 89개 `sections`를 이어 붙인 내레이션은 공백만 제외해도 다르다.
- 따라서 이전 구조에서는 TTS가 전체 대본을, 이미지는 장면 원문을 사용할 수 있었다.
- 이 상태에서 TTS를 새로 생성하거나 MP4를 조립하면 “원문 100% 일치”를 증명할 수 없으므로 차단이 맞다.

## 적용한 보완

- 새 대본 생성은 최종 장면 원문으로 전체 대본을 다시 확정하고, 장면별 `scene_id`·원문 SHA-256을 남긴다.
- TTS 메타데이터의 `canonical_text_sha256`과 자막 청크를 이미지 생성 직전에 대조한다.
- 이미지 단계가 우회되더라도 MP4 조립 직전에 실제 장면 원문과 TTS·자막을 다시 대조한다.
- 이 계약은 기사형·상황형·정보형을 추가해도 기존 Claude 대본 스타일, TTS 속도·음성, V5/archetype, 일반형 이미지, Fal 인트로를 대체하지 않는다.

## 다음 작업

1. 새 승인 대본을 장면 원문에서 확정한다.
2. 그 대본으로 TTS를 생성하고 강제 정렬 자막을 만든다.
3. 이 문서의 9장 계보 검증을 통과한 뒤 음성 청취·자막 원문·프레임 타이밍을 검수한다.
4. 사용자 별도 승인 후에만 Kling·MP4 조립을 시작한다.
