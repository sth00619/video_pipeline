# WO-IMG-01-D 결과 — 8장 비용 정정과 Job52 얼굴 참조 v2

## 1. 결론과 완료 범위

8장 파일럿의 품질 판정은 유지한다. 비용 계산은 thinking 토큰 누락으로 정정했다. 얼굴 작업은 유료 호출 전에 가능한 조사·참조 제작·프롬프트 계약·선행 실패 재현·커밋 격리 검증까지 완료했다.

- 비용 정정: `$1.12418` → **`$1.143872`**, 1달러=1,400원 환산 **`₩1,601.42`**
- 얼굴 v1 원인: 사용자 지정 장면이 아니라 Job52 scene 06·18·29로 구성됨
- 실제 전송: 8장 파일럿 8건 모두 v1 해시를 첫 참조로 전송
- 얼굴 v2: Job52 scene 03·04·05·09·13·14의 원본 얼굴 픽셀로 제작
- 운영 기본 참조: `channel_character_face_range_v2.png`로 전환
- 유료 API: **0회**
- scene42: 동결 유지
- 텍스트·수치·물리 표면·OCR·Fal 게이트: 완화하거나 우회하지 않음
- 미완료: scene 02·07·35의 2~3장 유료 재실행과 결과 얼굴 실측. 별도 예산 승인 전에는 실행하지 않음

따라서 이 WO의 오프라인 구현은 완료했지만, 유료 재실행이 필요한 최종 DoD는 아직 완료로 선언하지 않는다.

## 2. 8장 파일럿 비용 재검산

8건 합계는 `promptTokenCount=13,768`, `candidatesTokenCount=10,747`, `thoughtsTokenCount=1,641`, 이미지 출력 `8×1,120=8,960` 토큰이다. `totalTokenCount`는 각 응답에서 `prompt + candidates + thoughts`와 일치한다.

| 비용 항목 | 토큰 | Standard 단가 | 금액 |
|---|---:|---:|---:|
| 입력 | 13,768 | $2/백만 | $0.027536 |
| 이미지 출력 | 8,960 | $120/백만 | $1.075200 |
| 이미지 이외 candidate 출력 | 1,787 | $12/백만 | $0.021444 |
| thinking 출력 | 1,641 | $12/백만 | $0.019692 |
| 합계 | - | - | **$1.143872** |

기존 `$1.12418`은 마지막 thinking 행 `$0.019692`를 더하지 않은 값과 정확히 일치한다. 이 응답에서 thinking이 비과금이라는 새 근거를 확보한 것이 아니며, 의도적인 하한 표기도 아니었다. **단순 누락으로 정정한다.** 중간 thought image는 무료라는 공식 설명과 `thoughtsTokenCount` 과금은 구분한다.

원장의 `₩12,800`은 8장 각 1회의 보수적 예약 상한이며 예상 비용 또는 콘솔 확정 청구액이 아니다.

공식 근거:

- <https://ai.google.dev/gemini-api/docs/pricing>
- <https://ai.google.dev/gemini-api/docs/image-generation>

기존 보고서 `docs/WO_IMG_01_C3_EIGHT_SCENE_PILOT_RESULT_2026-08-27.md`의 비용 문장도 같은 값으로 정정했다.

## 3. v1 참조 원인 조사

### 3.1 v1은 지정 6장으로 구성되지 않았다

`channel_character_face_range_v1.png`를 512×512 세 패널로 분리해 Job52 scene 00~47 원본과 ORB 특징점으로 대조했다.

| v1 패널 | 최고 일치 Job52 장면 | good ORB matches | 해석 |
|---:|---:|---:|---|
| 0 | 06 | 512 | 지정 세트 03/04/05/09/13/14가 아님 |
| 1 | 18 | 578 | 경찰모·긴장 얼굴을 기본 범위에 포함 |
| 2 | 29 | 533 | 지정 세트가 아닌 실험실 얼굴 |

방법은 ORB 6,000 features, Hamming KNN, Lowe ratio 0.75다. 이 수치는 출처 확인용이며 얼굴 품질 점수가 아니다. 원문은 `docs/evidence/wo_img01_d_face_reference_20260828/v1_origins.json`에 있다.

### 3.2 참조는 선택 과정에서 빠진 것이 아니라 실제로 전송됐다

8장 파일럿 manifest의 고수준 `references`와 실제 `request_evidence.references`를 함께 검사했다. scene 00·02·05·07·15·21·35·47 모두 첫 참조가 다음 v1 해시였다.

`3d113c43e9395435d1b07b6e5a015c17e606b246e7a4f177bd3de4d074489c45`

따라서 얼굴 흔들림의 원인을 “참조가 요청에서 누락됐다”로 설명할 수 없다. **부적절한 v1 구성과 느슨한 프롬프트 계약이 실제 요청에 함께 들어간 것**이 확인된 원인이다. 장면별 세 참조 해시와 payload 해시는 `pilot_payload_references.json`에 보존했다.

### 3.3 프롬프트 충돌

기존 provider 계약은 v1을 “broader family”로만 취급하고 눈 구조·홍채·볼터치·눈썹까지 장면별로 달라질 수 있다고 명시했다. 그 뒤 공통 `FINAL CHARACTER QUALITY BOUNDARY`도 눈 구조·홍채·눈썹 각도·볼터치가 달라져도 된다고 반복했다.

즉 참조를 보내더라도 뒤쪽 문장이 얼굴 세부 고정을 다시 풀었다. 배경·소품 참조가 추가되는 선택 로직 자체는 얼굴 참조를 첫 장으로 유지했지만, **계약 우선순위가 얼굴보다 장면 변형에 더 관대했다.**

## 4. 얼굴 참조 v2

### 4.1 입력 계보

사용자가 지정한 Job52 scene 03·04·05·09·13·14만 사용했다. 빌더는 실행 전에 각 원본 SHA-256과 1920×1080 크기를 강제 확인한다. 고정 좌표 크롭, Lanczos 리사이즈, 얼굴 타원 밖 중성색 마스크만 사용한다. 생성형 보정·얼굴 재그림·색 재생성은 없다.

배경 문자·숫자·그래프를 새 참조가 다시 복사하지 않도록 얼굴 타원 밖을 `RGB(232,238,244)`로 가렸다. 얼굴 안쪽의 눈·눈썹·이마·볼 픽셀은 원본 그대로다.

- 결과: `backend/fastapi-workers/out/references/channel_character_face_range_v2.png`
- 크기: 1536×1024, 3열×2행
- SHA-256: `7e7981e389d07c4c3eca908708365cdcc809226c0f9a039f7ff7f62bbad8e40e`
- 생성 manifest: `channel_character_face_range_v2.manifest.json`
- 재생성 스크립트: `scripts/build_character_face_reference_v2.py`

v1은 덮어쓰거나 삭제하지 않았다. 참조 정리 감사에서 `superseded_face_reference`로 분류해 비교·롤백 자산으로 보존한다. v2만 `runtime_required` 기본 참조다.

### 4.2 얼굴 특징 정량 계약

원본 PNG에서 사람이 눈 전체와 홍채 경계의 픽셀 박스를 선택하고, 비율 계산과 판정은 스크립트가 수행했다. 학습형 얼굴 랜드마크 검출기가 아니므로 육안 검수를 대체하지 않는다.

| 구분 | 장면 | 평균 홍채 폭 / 눈 전체 폭 | 주요 판정 |
|---|---:|---:|---|
| 승인 참조 | 03 | 45.71% | 통과 |
| 승인 참조 | 04 | 47.78% | 통과 |
| 승인 참조 | 05 | 48.78% | 통과 |
| 승인 참조 | 09 | 48.33% | 통과 |
| 승인 참조 | 13 | 46.67% | 통과 |
| 승인 참조 | 14 | 46.67% | 통과 |
| 기존 파일럿 실패 | 02 | 32.56% | 작은 무채색 눈동자, 다층 반사광 없음, 깊게 찌푸린 눈썹 |
| 기존 파일럿 실패 | 07 | 100% | 흰자 없는 검은 타원 자체가 눈 전체라 구조 실패 |
| 기존 파일럿 실패 | 35 | 33.33% | 작은 무채색 눈동자, 다층 반사광 없음 |

승인 6장의 관측 평균 범위는 45.71~48.78%다. 표현·원근 여유를 포함한 생성 허용 범위는 **38~58%**로 두었다. 추가 계약은 다음과 같다.

- 보이는 흰자와 따뜻한 갈색 홍채/눈동자
- 여러 겹의 흰색 반사광
- 부드러운 이마 반사 하이라이트 필수
- 완만한 곡선 눈썹, 날카로운 각·깊은 찌푸림 금지
- 장면 조명과 양립할 때 은은한 볼터치 유지
- 얼굴 구조가 배경·소품 디테일보다 우선

측정 좌표·양쪽 눈 비율·범주 판정·원본 해시는 `face_measurements.json`에 있다.

### 4.3 의상 다양성은 고정하지 않았다

scene 03/04/05/09/13/14 자체가 페도라, 베레모, 고글, 기상 모자, 정장 등 서로 다른 의상을 포함한다. 새 계약은 다음을 명시한다.

- `Costume and headwear remain scene-specific`
- `Do not force one outfit`

공통 integrity 계약도 의상·머리 장식·자세·입 모양·크기·프레이밍은 장면별로 유지한다. 사용자가 지시하지 않은 “금융 진행자 의상 고정”은 도입하지 않았다. 경찰 의상 금지는 기존처럼 해당 장면의 wardrobe에 경찰 근거가 없을 때만 적용한다.

## 6. Job52와 이후 영상에서 구체적으로 달라지는 점

이 변경은 Job52 번호 분기가 아니라 모든 신규 Gemini 이미지 요청의 공통 기본 참조와 공통 얼굴 계약에 적용된다.

- Job52/파일럿 scene 07 같은 **흰자 없는 검은 타원 눈**은 허용 얼굴 구조가 아니다.
- scene 02 같은 **작은 검은 눈동자 + 깊은 V자 눈썹**은 38% 하한·갈색 홍채·곡선 눈썹 계약에서 벗어난다.
- scene 35처럼 **경찰모 때문에 다른 캐릭터 인상**이 생기는 경우, 장면 wardrobe 근거가 없으면 기존 장면 로컬 경찰 의상 금지와 함께 차단 방향이 강화된다.
- scene 03/04/05/09/13/14의 큰 갈색 눈, 흰자, 다층 반사광, 이마 하이라이트, 필요 시 볼터치를 공통 얼굴 범위로 사용한다.
- 정장·실험복·고글·모자 등 장면별 의상과 포즈는 계속 달라질 수 있다.
- 기존 Job52의 화풍·구도·색감은 별도 style reference 두 장이 계속 담당하며, 얼굴 v2가 이를 전역적으로 덮어쓰지 않는다.

## 8. 다음 단계와 승인 필요 사항

다음 유료 단계는 scene 02·07·35 중 2~3장만 새 scene key와 새 계약으로 각 1회 생성하는 것이다. 실행 전 별도 예산 승인이 필요하다.

재실행 통과 조건:

1. 얼굴이 홍채/눈 폭 38~58%, 흰자, 갈색 홍채, 다층 반사광, 이마 하이라이트, 곡선 눈썹 계약에 들어올 것
2. 육안으로 Job52 scene 03/04/05/09/13/14와 같은 캐릭터로 보일 것
3. 의상은 각 장면 대본에 맞고 하나의 정장/모자로 수렴하지 않을 것
4. 기존 결정론 텍스트·물리 표면·OCR 검증을 모두 그대로 통과할 것
5. 실패 장면은 자동 재시도하지 않고 `needs_review`로 격리할 것
6. 얼굴 승인 전 Fal/TTS/조립을 시작하지 않을 것

8장 전체 재실행은 이 문서 범위가 아니다. 2~3장 결과가 얼굴 계약을 통과한 뒤 별도 예산과 WO로 판단한다.
