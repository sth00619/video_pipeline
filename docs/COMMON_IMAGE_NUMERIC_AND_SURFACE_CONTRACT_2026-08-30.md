# 공통 이미지 숫자 차단·표면 의미 계약 반영 보고

작성일: 2026-08-30
적용 대상: 영상 생성 버튼이 호출하는 공통 이미지 생성 경로
유료 API 호출: 0회

## 1. 결론

이번 수정은 Job52·특정 scene의 결과 파일을 고친 작업이 아니다. 모든 새 영상에서
`images_worker`가 Gemini 요청 직전과 원본 이미지 저장 직전에 공통으로 실행하는
계약을 강화했다.

1. 승인 목록에 없는 숫자를 OCR이 읽으면 일반 장면에서도 즉시 거절한다.
2. 프롬프트의 소수 값을 제거하면서 `.11` 같은 숫자 꼬리가 남던 결함을 고쳤다.
3. 의미형 문자 계획이 여러 문구를 좌표 없는 `main` 표면 하나에 몰아넣으면 요청
   전에 실패한다.
4. 한 물리 표면에 라벨과 값을 함께 넣는 정상 장면은 서로 겹치지 않는 상대 영역을
   명시했을 때 계속 허용한다.

운영 모델 정책은 기존 결론대로 `gemini-3-pro-image` + Priority를 유지한다. Flash는
공통 운영 자동 혼합에 넣지 않았다.

## 2. 발견한 실제 결함

### 2.1 OCR이 숫자를 찾고도 일반 레인에서 통과

`visible_text_contract_result()`는 `0000.000`, 임의 연도, 가짜 계기값을
`review_required_numeric_texts`에 기록했지만 `reject_unapproved=True`인 엄격 문자
레인에서만 `unexpected_texts`로 올렸다. 따라서 일반 장면에서는 숫자를 발견하고도
`passed=True`가 될 수 있었다.

수정 후에는 비수치 문구만 후단 의미 검수로 넘길 수 있고, 승인되지 않은 숫자는
레인 종류와 무관하게 항상 `unexpected_texts`가 된다. 승인된 금융 수치 역시 Gemini
기본 래스터에 있으면 기존 `detected_deterministic_texts()`가 먼저 거절하며, 최종
수치는 Pillow/FFmpeg 결정론 경로만 사용한다.

### 2.2 소수점 꼬리 누출

기존 디스플레이 지시 정규식은 `A monitor with 8888.11`에서 숫자 토큰 전체가 아니라
앞부분만 소비할 수 있었다. 실제 재현 결과 정제 프롬프트에 `.11`이 남았다. 숫자,
대문자 라벨, 한국어 낱말을 토큰 경계까지 완전히 소비하도록 바꿨다. `2D`, `16:9`,
두 개의 병 같은 제작 규격·사물 개수는 그대로 보존한다.

### 2.3 여러 의미를 `main` 하나에 몰아넣는 표면 계획

기존 `semantic_roles_v1`은 서로 다른 문구 여러 개가 모두 `surface: main`이어도
유효하게 받았다. 이 상태에서는 프롬프트와 렌더러가 어느 사물의 어느 영역에 문구를
넣을지 추측하게 된다.

수정 후 각 항목에는 정규화된 `surface_id`와 `semantic_object_id`가 생긴다. 같은
표면을 공유하는 문구가 둘 이상이면 각 항목에 표면 내부 상대 `region`이 있어야 하며,
영역이 겹치면 요청 전에 실패한다. 이 규칙은 Job52 scene07에서 확인한 4개 문구의
단일 `main` 몰아넣기를 일반화해 막는다.

## 3. 검증

### 선행 실패

- 비엄격 장면의 `0000.000`, `2027`: 수정 전 `unexpected_texts=[]`, `passed=True`
- `A monitor with 8888.11`: 수정 전 정제 프롬프트에 `.11` 잔존
- 영역 없는 복수 `surface: main`: 수정 전 계약 생성 성공

### 수정 후

- 호스트 집중 검사: 41 passed, 1 skipped
- 운영 Docker 재빌드 후 관련 검사: 53 passed
- 컨테이너 상태: healthy
- 유료 Gemini·Claude·TTS·Fal 호출: 0회

전체 pytest는 이번 코드와 무관한 기존 수집 환경 문제로 완주하지 못했다. 호스트에는
`faster_whisper`/`cv2`가 없고, 운영 컨테이너에서는 일부 과거 canary 테스트가
`Path.parents[n]`으로 특정 외부 디렉터리 깊이를 가정해 14건의 수집 오류가 발생한다.
관련 기능 묶음은 실제 운영 의존성이 있는 Docker 안에서 별도로 전부 통과시켰다.

## 4. Job52에 대입한 개선 예

- scene00 계열: `PER 4배` 같은 금융 수치가 Gemini 프롬프트에 번역된 `4x`로 남지
  않고, 기본 이미지에 모델이 임의 수치를 쓰면 OCR 단계에서 거절된다.
- scene07 계열: `코스피`, 기업 제외 의미, `143조 원` 등 여러 정보가 좌표 없는
  하나의 `main` 화면에 뭉치는 계약은 더 이상 허용되지 않는다.
- scene21·38·39·40 계열: 가짜 계산기 숫자·계기값·연도가 OCR에 잡히면 엄격 문자
  파일럿인지 여부와 관계없이 저장되지 않는다.

이 수정은 Job52 이미지를 다시 사용하거나 scene 번호를 하드코딩하지 않는다. 같은
오류 유형이 어떤 주제의 새 영상에서 발생해도 동일한 공통 경계가 작동한다.

## 5. 세 가지 큰 목표와의 관계

1. **시간·분량·TTS·자막·이미지 동기화**: 이번 변경은 승인 내레이션과 TTS 원문을
   수정하지 않는다. 장면 청크의 단일 기준을 보존한다.
2. **장면 의미에 맞는 이미지와 안정적인 영상화**: 문구를 실제 의미 사물의 표면과
   연결하는 기반을 강화했다. 다음 단계는 다중 표면을 자동 검출·연결하는 공통 계획기다.
3. **오탈자·이탈자·수치 정확성**: 이번 변경의 직접 대상이다. 숫자 사전 차단,
   생성 후 OCR fail-closed, 결정론 렌더라는 세 경계를 연결했다.

## 6. 후속 반영과 남은 작업

1. 자동 추출된 `screen_texts`를 사물별 `semantic_object_id`와 `surface_id`로
   계획하는 공통 장면 계획기의 1단계를 WO-IMG-02에서 구현했다.
2. 다중 물리 표면의 원본 픽셀 검출 결과를 각 의미 ID와 안전하게 연결하는 후단
   attestation은 남아 있다.
3. 작은·기울어진 다중 모니터 문자는 이미 원본 해상도 표면별/원근 보정 판독이
   공통 strict 경로에 연결되어 있다. 새 유형에서 재현율을 계속 측정한다.
4. 의사문자, 얼굴, 해부학 자동 게이트와 사용자 육안 승인 절차를 유지·확장한다.
5. 위 정지 이미지 계약이 통과한 장면만 Fal 후보로 보내며 문자·수치 표면은 고정한다.

따라서 숫자 차단, 잘못된 표면 계획 차단, 생성 전 자동 의미 배정까지 공통 운영에
반영됐다. 생성 후 여러 실제 픽셀 표면을 의미 ID에 결박하는 단계까지 완료됐다는
보고는 아니다.
