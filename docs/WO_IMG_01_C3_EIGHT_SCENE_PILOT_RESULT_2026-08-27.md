## 4. OCR 실측의 해석

전체 프레임 Tesseract는 복잡한 만화 선화에서 승인 문구를 크게 분할했다. 최초 exact-row 측정은 네 장 모두 실패했다. 이를 성공으로 고쳐 쓰지 않았다.

이후 유료 호출 없이 동일 이미지의 TSV 행을 재분석해, 이웃 한국어가 붙어 있을 때는 거절하면서 완전한 연속 OCR 토큰만 결합하는 경로를 추가했다. 그 결과 자동 검출은 다음과 같다.

- scene 15: `엇갈림` 검출
- scene 35: `경고` 검출, `전망치` 미검출
- scene 47: `상반기 실적` 검출, `질문` 미검출
- scene 02: `경고` 미검출

육안상 정확하다는 판단과 OCR 자동 통과는 별개다. 네 장 모두 육안 문자열은 정확하지만, 자동 게이트 관점에서는 scene 15만 승인 문구 전체를 잡았고 그 장면도 비승인 의사문자 때문에 최종 실패다. 8장으로 전역 글자 높이 임계값을 확정하지 않는다.

## 5. 원인과 이번 코드 수정

### 5.1 결정론 표면 실패

수치·정보 문구는 모델 프롬프트에서 제거되어 실제로 `4배`, `143조 원`, `5663포인트`, `1812포인트` 노출이 0건이었다. 이 부분은 의도대로 작동했다.

그러나 같은 프롬프트가 한편으로는 “표면을 도형과 색 블록으로 풍부하게 유지”하라고 하고, 다른 한편으로는 “나중 결정론 문자용 차분한 영역”을 요구했다. 모델은 전자를 따라 모든 모니터·칠판·표찰 내부를 도형으로 채웠다. 로컬 검출기는 장면 의미를 보지 않고 안전한 사각형 하나를 고르므로 scene 00·05에서는 작은 보조 패널을 후보로 잡았고 실제 attestation에서 거절됐으며, scene 07·21은 후보 자체가 없었다.

유료 실행 후 다음 최소 수정까지 완료했다. 아직 새 API 결과로 검증하지 않았으므로 “해결 완료”라고 판정하지 않는다.

- 결정론 문자열·수치를 모델 프롬프트 뒤에 다시 열거하던 누출 제거
- 주변 장면은 상세하게 유지하면서, 장면에 원래 필요한 물리 표면 **정확히 하나**의 내부만 균일·무문자·무가림으로 만들도록 계약 통일
- 한 표면 안에서 최대 네 문구를 상대 좌표 셀로 나누는 결정론 배치 추가
- 일반 결정론 수치 셀도 `facts[n]` 장면 로컬 근거와 정확 일치할 때만 허용
- Job52 보존 프롬프트에 남은 과거 `은 → Silver` 오염은 현재 엔티티 바인더로 재검증해 제거

### 5.2 짧은 승인 문구 레인

Gemini는 네 장 모두 승인 한국어를 육안상 정확히 썼다. 하지만 “이 문자열 외에는 쓰지 말라”는 계약만으로는 배경 모니터의 `RISK`, 눈금 숫자, 의사문자를 막지 못했다. 따라서 이 레인을 전역 활성화하지 않는다. 허용 문구 정확성과 비허용 문자 0건을 동시에 통과할 때만 사용할 수 있다.

## 6. Fal 준비 판단

Fal/Kling은 호출하지 않았다. 현재 안전 게이트는 `screen_texts`, `screen_text_plan`, 수치 오버레이 또는 OCR 문자가 있는 이미지를 정지 대상으로 분류하므로 이번 8장은 그대로 Fal에 넘어가지 않는다. 이는 현재 상태에서 올바른 fail-closed 동작이다.

이미지가 승인된 뒤 사용할 동작 후보는 다음과 같다.

- scene 00: 저울 접시의 짧은 흔들림 또는 캐릭터 한 손 설명 동작
- scene 05: 설비 표시등·컨베이어의 국소 움직임과 한 번의 손짓
- scene 07: 서버 표시등과 캐릭터 설명 손동작, 중앙 정보 표면은 완전 정지
- scene 21: 경광등 점멸·게이지 바늘·캐릭터 놀람 동작, 수치 모니터는 완전 정지
- scene 35: 구름·빗줄기·한 손 설명 동작, 두 라벨 영역은 완전 정지
- scene 47: 번개·배럴의 아주 작은 흔들림·캐릭터 한 손 동작, 두 문구 표면은 완전 정지

실제 Fal 파일럿은 고정 카메라, 텍스트 표면 고정, 한 캐릭터 또는 한 소품만 움직이는 계약으로 시작한다. 결과는 `motion_locality.py`의 전역 변화율·활성 타일·테두리 변화율로 화면 전체 지글링을 거절해야 한다. 모델이 생성한 문구를 가진 장면은 텍스트 영역을 매 프레임 고정 복원하는 별도 합성 계약이 없으므로 아직 실행 대상이 아니다.
