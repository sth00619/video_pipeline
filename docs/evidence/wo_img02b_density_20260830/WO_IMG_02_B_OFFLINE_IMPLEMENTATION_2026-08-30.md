# WO-IMG-02-B — 화풍·구성 밀도 레이어 오프라인 구현

## 결론

기존 archetype 11종은 유지하고, 각 archetype 위에 독립적인 `composition_density_profile`을 추가했다. 텍스트 정확성 계약과 밀도 계약은 별도 필드·별도 프롬프트 절로 기록한다. 이 구현은 특정 Job이나 scene 번호를 분기하지 않는다.

## 레퍼런스 재검토

사용자 제공 69프레임과 기존 배타적 분류를 다시 대조했다. 표본은 15초 간격으로 보이므로 장면 전환 전수라고 주장하지 않는다. 정확한 프레임별 객체 검출값을 가장하지 않고, 유형별 반복 구성을 운영 프롬프트가 지킬 수 있는 보수적 최소 “소품·장치 묶음”으로 바꿨다.

## 구현

- 새 모듈: `app/utils/composition_density_profile.py`
- 운영 archetype 11종 모두 최소 요소 수, 근경/중경/원경, 최소 정보 표면 수, 색 대비, 허용 물리 표면을 정의했다.
- Job52 보존 입력의 과거 `split_stage`는 archetype을 되살리지 않고 호환 프로필 `split_comparison`으로만 해석한다.
- `_bounded_text_generation_prompt()`가 모든 운영 Gemini 요청 직전에 프로필을 공통 품질 계약에 추가한다.
- `plan_v5_scene_contract()` 원장에도 같은 프로필을 보존한다.
- 밀도 수를 채우기 위한 단어·의사문자·숫자·축 라벨·미세문자·로고·빈 화면·분리형 카드는 명시적으로 금지한다.
- 기존 승인 문구와 결정론 금융 수치는 변경하지 않는다.
