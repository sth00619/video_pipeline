# WO-IMG-02-C — 종합 재점검·레퍼런스 재벤치마킹·4장 실증 결과

## 1. 결론과 정정

WO-IMG-02-B 보고서는 구성 밀도 회복만을 주 판정축으로 삼아 다음 문제를 놓치거나 비중을 낮게 보고했다.

- scene00의 저울과 칠판이 같은 설명 역할을 중복할 위험
- scene07의 핵심 결론 수치 `143조 원` 누락
- `surface_gate_passed: 0/4`가 뜻하는 최종 합성 불가능성
- scene28의 날카로운 눈매와 과도한 적색 채도

따라서 당시 scene15·28을 “명확한 개선”이라고만 표현한 것은 불완전했다. 밀도는 개선됐지만 최종 영상 프레임으로 승인할 수 있는지는 별도 문제였다. 이번에는 HTTP, 생성 원본 문자, 생성 문자 좌표 결박, 결정론 표면 합성, 최종 육안을 서로 다른 단계로 분리했다.

실 API 4건은 모두 HTTP 200이었으나 **최종 승인 결과는 0/4**다.

## 3. scene00 — 중복 비유와 수치 표면

### 3.1 승인 대본이 요구하는 정보

보존 입력의 승인 항목은 `삼성전자`, `SK하이닉스`, `PER 4배`다. 장면의 핵심은 두 기업의 비교값이며, 별도의 PER 정의 문장을 화면에서 동시에 가르쳐야 한다는 근거는 없다. 따라서 저울 하나가 주 설명 장치이고 칠판은 무문자 배경 소품이어야 한다.

### 3.2 공통 수정

`trade_calculator`는 다음 역할로 고정했다.

- 왼쪽 저울 접시: `삼성전자`
- 오른쪽 저울 접시: `SK하이닉스`
- 저울 받침대: 결정론 `PER 4배`
- 칠판: 읽을 수 있는 정보가 없는 주변 교실 소품

동일 비교를 칠판·저울·그래프에 반복하는 프롬프트를 차단하는 `max_primary_explanation_devices=1`과 역할 계약을 공통 density profile에 추가했다. scene 번호 하드코딩은 없다.

### 3.3 실증 결과

raw 이미지는 저울 중심 비교를 만들었고 회사명도 정확했다. 하지만 휴리스틱 표면 검출이 `balance_scale_plinth`가 아니라 프레임 중앙 영역을 선택해 `PER 4배`가 공중에 뜬 형태로 합성됐다. 결정론 픽셀 출처 검증은 통과했지만 **의미 표면 좌표 결박은 실패**다. “정확한 글자를 그렸다”만으로는 승인하지 않는다.

## 4. scene07 — `143조 원` 누락 원인

### 4.1 라우팅은 맞았고 최종화가 없었다

공통 계약은 다음처럼 분리한다.

- Gemini 생성: `삼성전자`, `SK하이닉스`, `코스피`
- Pillow 결정론 렌더: `143조 원`

따라서 raw Gemini 이미지에 `143조 원`이 없는 것은 의도된 중간 상태다. WO-IMG-02-B 실행기는 raw 생성 후 실제 Pillow 최종 합성을 하지 않았으므로 당시 결과에 수치가 존재할 수 없었다. 이를 보고서가 핵심 실패로 올리지 않은 것이 문제였다.

### 4.2 현재 최종화 결과

현재 운영 계약으로 재최종화하자 `summary_monitor`에 대응하는, 캐릭터·기존 문자를 침범하지 않는 안전한 `device_screen`을 찾지 못해 `DeterministicSurfaceMissingError`가 발생했다. 최종 파일은 승인되지 않았고 `143조 원`도 합성되지 않았다.

이제 “결정론 값이 계획에 존재하지만 최종 표면 합성이 완료되지 않은 상태”는 최종 승인으로 갈 수 없다. 다음 필요한 수정은 `summary_monitor`의 실제 픽셀 사각형을 장면 계획과 결박하는 것이다.

### 6.2 색조 이탈 원인 범위

`risk_control_room` 프로필은 “deep blue control-room base with decisive red risk”를 지시하고 risk-map 참조 자체도 경고 인상을 가진다. 생성 결과의 HSV saturation은 평균 170.68, p90 255로, risk-map 참조(평균 92.37, p90 140)와 market-flow 참조(평균 134.66, p90 200)보다 높았다. 따라서 **위기 archetype 문구와 경고 참조가 함께 적색 강도를 증폭했을 가능성**이 크다. 단일 원인으로 확정하지 않는다.

위기 장면의 적색은 의도될 수 있지만 캐릭터 종·선화·눈 구조까지 날카롭게 변하는 것은 허용하지 않는다. 이번 얼굴은 흰자와 갈색 홍채가 보이나 다른 세 장보다 눈매와 눈썹이 날카롭다. 수동 눈 ROI가 없어 홍채 비율 수치를 새로 주장하지 않는다. 다음 게이트는 배경 팔레트 변화와 캐릭터 팔레트/선화를 분리해 평가해야 한다.

## 7. 기존 미해결 트랙 체크리스트

### 6.3 사후 정정 — 오른손의 모호한 검은 소품

사용자 실물 검토에서 scene28 캐릭터 오른손 주변의 검은 소품이 총·무전기·드릴처럼도 읽힌다는, 기존 보고서에 없던 실패가 발견됐다. 실물 파일은 `scene_28_post_overlay_review.png`(SHA-256 `71db1f77fbead3dc5f46e36ed2fe067a6dd827098e18caf5435a112d33df8df8`)이고 최종 프롬프트 SHA-256은 `2383a02668e0b3e5530ce772bc08ed5c76bf6226e44c102fa930fa881e927197`이다.

픽셀상 물체는 콘솔 베이스에 붙은 붉은 갈색 제어 레버에 가깝다. 그러나 프롬프트에는 그 레버의 형태·부착·역할을 직접 요구한 문장이 없고, 공통 `risk_control_room` 밀도 프로필의 `one narration-essential risk prop`라는 모호한 요구만 있었다. 따라서 “모델이 총을 그렸다”고 확정하지는 않지만, **장면 의미로 정체를 판별할 수 없는 소품을 공통 프롬프트가 허용한 결함**으로 판정한다.

이 항목을 기존 4개 거절 사유와 별개인 다섯 번째 거절 사유로 추가한다. 이후 유료 canary는 `unexpected_or_ambiguous_props`와 `unlisted_failure_scan`을 필수 육안 항목으로 기록하며, 자동 판정과 사용자 판정이 다르면 이견 원장을 남긴다.

| 항목 | 판정 | 근거/남은 일 |
|---|---|---|
| `SK 하인스` → `SK하이닉스` | 회귀 추가·집중 테스트 통과 | 실제 함수에 `SK 하인스` OCR 행을 주입하면 거절하는 테스트를 추가. 이번 scene15 raw의 육안 문자열은 `SK하이닉스`였으나 1장 증거일 뿐 |

따라서 전체 suite green이라고 주장하지 않는다. 이번 공통 경로 관련 집중 회귀는 통과했지만, 전체 회귀 환경 복원은 별도 작업이다.

## 10. 다음 구현 순서

   - `balance_scale_plinth`, `summary_monitor`를 이름이 아닌 실제 표면 위치로 검증

이번 결과는 “구성 밀도 프로필이 실패했다” 또는 “완료됐다” 중 하나가 아니다. 밀도와 장치 역할은 공통 경로에 진전이 있었지만, **핵심 사실을 정확한 물리 표면의 최종 픽셀로 완성하는 계약은 아직 미완료**다.
