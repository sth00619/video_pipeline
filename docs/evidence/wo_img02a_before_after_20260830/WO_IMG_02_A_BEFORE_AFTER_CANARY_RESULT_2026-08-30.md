# WO-IMG-02-A — Job52 기준 Before/After 실 이미지 결과

작성: 2026-08-30  
범위: scene 00·07·15·28, `gemini-3-pro-image` + Priority, 장면별 1회, 자동 재시도 없음

## 1. 결론

4건 모두 공급자 HTTP 200으로 이미지를 받았지만 품질 결과는 혼합이다. 이번 실증으로 다음을 확정한다.

- scene00의 회사별 물리 표면 분리와 금융 수치 비노출은 육안상 크게 개선됐다.
- scene07의 다중 표면 의미 배정은 **부분 개선일 뿐 해결되지 않았다.** 두 개의 별도 용기와 중앙 모니터는 생겼지만 용기에 `삼성전자`·`SK하이닉스`가 없어 대본 의미를 식별할 수 없다.
- scene15의 대괄호·따옴표는 육안상 사라졌지만, 실제 Tesseract는 정확한 두 문구를 모두 놓쳤다.
- scene28은 원본 해상도 OCR 경로가 `대형주`를 정확히 검출해 기존 재현율 개선이 실 이미지에서도 작동했다. 그러나 배경 차트에 비승인 숫자가 생성되어 전역 수치 계약은 아직 통과하지 못한다.
- 네 장면 모두 생성 후 다중 표면 좌표 attestation을 완성하지 못했다. 사전 계획 계약과 생성 후 픽셀 바인딩은 여전히 별개 단계다.

따라서 WO-IMG-02의 공통 계약 반영은 실 이미지에서 효과가 확인됐지만, WO-IMG-02-A를 전체 성공으로 판정하지 않는다.

## 3. 자동 게이트와 육안 판정 분리

실행 호스트에는 OCR 엔진이 없어 manifest의 실행 시점 text gate는 4건 모두 `status=unavailable`로 실패했다. 이 원장을 성공으로 덮어쓰지 않았다. 생성 후 동일 raw 파일을 `pipeline_fastapi` 컨테이너의 실제 Tesseract 경로로 별도 재판독했으며, 결과는 `docker-ocr-recheck.json`에 보존했다.

## 4. 요구 질문에 대한 명시적 답

### 4.1 다중 표면 자동 배정이 scene07 원래 문제를 해결했는가?

**아니오. 부분 개선이다.**

사전 계획은 두 기업을 서로 다른 소품에, 시장 요약을 모니터에 배정하도록 바뀌었고 실제 이미지에도 용기 두 개와 모니터가 생겼다. 그러나 두 용기에 회사명이 없어서 무엇을 상징하는지 알 수 없다. 또한 생성된 표면별 실좌표를 후속 합성·검증 경로에 연결하는 attestation이 실패했다. 구조 후보 생성은 작동했지만 의미 전달과 생성 후 바인딩은 미완료다.

### 4.2 scene28 OCR이 이탈자 문제를 실제로 검증할 수 있는가?

**목표 문구에 대해서는 예. 전체 프레임 품질에 대해서는 아직 아니오다.**

이번 raw에는 정확한 `대형주`가 생성됐고 원본 해상도 다중 표면 OCR이 이를 검출했다. 같은 경로는 `대형주수`가 들어오면 승인 문구와 정확히 일치하지 않으므로 거절한다. 다만 배경의 작은 비승인 숫자까지 안정적으로 전역 검출하지 못했으므로, “이미지의 모든 문자·수치가 안전하다”는 결론으로 확대하지 않는다.

## 5. Job52 만족 요소의 보존 여부

- scene00은 Job52의 저울 비유와 높은 정보 밀도를 유지하면서 회사명을 한국어로 정확히 분리했다.
- scene15는 상승/하락의 대조 구도, 캐릭터 표정·의상 다양성, 굵은 외곽선과 셀 셰이딩을 유지했다.
- scene28은 위험 관제실의 붉은 경고 분위기와 캐릭터 일관성을 유지했다.
- scene07은 실험실 정보 밀도와 소품 분리는 회복했지만, Job52가 잘했던 “이미지만 봐도 대본 의미가 읽힘”에는 아직 못 미친다.

즉 공통 캐릭터·화풍 계약은 이번 네 장면에서 큰 붕괴 없이 유지됐지만, 텍스트·사물의 의미 결합은 장면별 편차가 남았다.

## 6. 다음 공통 운영 과제

이번 실증 결과만으로 아키텍처를 즉시 추가 변경하지 않는다. 후속 WO 후보는 다음과 같이 원인별로 분리한다.

1. 자동 계획으로 생성한 문구도 운영 strict gate에서 `require_all_approved`를 적용해 scene07 같은 누락을 자동 통과시키지 않는다.
2. `semantic_object_id`·`surface_id`를 생성 후 실제 픽셀 좌표와 연결하는 다중 표면 attestation을 공통 경로에 완성한다.
3. scene00의 OCR 노이즈와 scene15의 OCR 누락을 분리해 false positive/false negative 보정 fixture로 만든다.
4. scene28처럼 목표 문구 주변뿐 아니라 전체 원본 해상도의 여러 정보 표면에서 비승인 숫자를 찾는 전역 다중 영역 OCR을 보강한다.

이 네 항목은 Job52 scene 번호 분기로 구현하지 않고, 영상 생성 버튼이 타는 공통 이미지 운영 경로의 계약으로 구현해야 한다.
