# WO-PROVIDER-02 대괄호 격리 결과

## 결론

공통 프롬프트 빌더에서 승인 문구를 배열·JSON으로 제시하던 형식을 평문 규칙으로 바꾼 뒤 scene15를 Pro/Flash 각각 한 번 생성했다. 두 결과 모두 기존의 대괄호(`[]`)는 사라졌다. 따라서 Stage 1에서 두 모델에 공통으로 나타난 대괄호는 모델 독립 결함이라기보다 프롬프트 표기에서 유도된 아티팩트라는 가설을 강하게 지지한다.

다만 완전 해결로 확대 해석하지 않는다.

- Pro: 육안상 `엇갈림`을 정확히 한 번 표시했다. 축소 Tesseract는 이를 0회로 읽어 strict 게이트가 실패했다. 이는 생성 문자열과 OCR 재현율을 분리해 판정해야 하는 사례다.
- Flash: 대괄호는 없어졌지만 `‘엇갈림’`처럼 따옴표를 추가했다. 대괄호 원인은 제거됐지만 임의 문장부호 금지 계약은 아직 위반했다.
- 두 결과 모두 자동 게이트 실패이며 사용자 육안 승인 전 최종 승인하지 않는다.

## 공통 코드 변경

`_bounded_text_generation_prompt()`가 승인 문자열을 다음 두 형식으로 노출하지 않도록 바꿨다.

- 제거: `case-sensitive string list: [엇갈림]`
- 제거: `[{"text": "엇갈림", ...}]`
- 적용: `Approved wording 1 is 엇갈림.` 뒤에 최대 횟수·용도·표면을 평문으로 기술
- 추가: 승인 문자열 주위에 괄호·대괄호·중괄호·따옴표를 그리지 말라는 명시적 금지

이 수정은 scene15 전용이 아니라 영상 생성 버튼이 타는 공통 이미지 프롬프트 빌더에 반영했다.
