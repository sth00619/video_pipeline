# WO-PROVIDER-02 — 91개 raw 전수 육안 원장과 최종 모델 결정

작성일: 2026-08-30
범위: scene42를 제외한 47개 장면 × Pro Priority/Flash High 94요청, 생성 raw 91개 전수 검토

## 1. 최종 결론

영상 생성 버튼의 공통 이미지 공급자는 **`gemini-3-pro-image` + Priority**로 확정한다.

- `gemini-3.1-flash-image` High를 자동 폴백이나 장면별 혼합 라우터로 사용하지 않는다.
- Flash는 수동 비교 연구 프로필로만 보존한다.
- 이후 이미지 품질 개선은 모델 재선택이 아니라 공통 프롬프트·참조·텍스트·표면·얼굴·해부학 게이트에 집중한다.
- 공급자 사양 또는 자체 대규모 실측이 유의하게 바뀌기 전에는 이 모델 결정을 다시 열지 않는다.

이 결론은 “Pro 이미지가 전부 좋다”는 뜻이 아니다. 현재 raw 직접 합격률은 두 모델 모두 낮고 겹친다. 선택 이유는 동일 장면 직접 비교, 공급 가용성, 지연시간, OCR 재현율과 운영 예측 가능성을 함께 봤을 때 Pro Priority가 단일 기본값으로 더 안정적이기 때문이다.

## 2. 판정 계층

이번 원장은 다음을 하나의 성공 숫자로 합치지 않았다.

1. `http_status`: 공급자가 HTTP 200을 돌려줬는가.
2. `raw_present`: 실제 PNG가 저장되고 SHA-256으로 원장과 일치하는가.
3. `visual_grade`: 사람 눈으로 봤을 때 현재 계약상 `pass`, 수정 후보 `review`, 재생성 `reject`인가.
4. `defect_types`: 오탈자, 의사문자, 임의 수치, 중복, 얼굴·화풍, 말풍선 등 구체적 원인.
5. `pairwise_choice`: 같은 장면·동일 프롬프트·동일 참조에서 어느 모델 결과가 더 좋은가.

전체 94행 원문은 `MANUAL_VISUAL_QUALITY_LEDGER_2026-08-30.csv`에 보존했다. `not_generated` 3행을 제외하면 raw 육안 판정은 정확히 91행이다. 전수 구도·캐릭터·화풍 판정은 12개 콘택트시트(각 raw 640×358 표시)로 수행했고, 작은 문자·수치처럼 축소본 판정이 위험한 항목은 원본 raw, 원본 SHA-256, manifest의 OCR 측정을 함께 대조했다. 따라서 “91개 파일을 각각 원본 배율로 눈으로 읽었다”는 과장된 주장은 하지 않는다.

## 3. 전수 집계

| 지표 | Pro Priority | Flash High |
|---|---:|---:|
| 요청 | 47 | 47 |
| HTTP 200/raw 저장 | 46 | 45 |
| 육안 `pass` | 23 | 25 |
| 육안 `review` | 7 | 3 |
| 육안 `reject` | 16 | 17 |
| 미생성 | 1 | 2 |
| 같은 장면 직접 비교 우세 | **24** | **10** |

두 모델 모두 `pass`인 장면은 17개, Pro만 `pass`는 6개, Flash만 `pass`는 8개, 둘 다 `pass`가 아닌 장면은 16개다. raw 합격 비율의 Wilson 95% 구간은 Pro 36.1~63.9%, Flash 41.2~69.1%로 크게 겹친다. 따라서 단순 합격 장수 23 대 25로 Flash 우세를 주장할 수 없다.

반면 동일 장면에서 실제 구도·정보 밀도·계약 준수까지 비교해 승자를 고른 34개 장면은 Pro 24 대 Flash 10이다. 동률을 제외한 양측 부호검정의 두 방향 p값은 약 0.0243이다. 이 값은 수동 루브릭 자체의 주관성을 제거하지는 않지만, 이번 동일 입력 표본 안에서는 Pro 선호가 우연만으로 설명되기 어렵다는 보조 근거다.

## 4. 모델별 실패 패턴

### Pro Priority

- 비승인 문자 10건
- 임의 수치 7건
- 의사문자 6건
- 중복 문자 4건
- 오탈자 2건
- 눈 구조 1건
- 화풍 이탈 1건
- 계획되지 않은 말풍선 1건

### Flash High

- 임의 수치 7건
- 의사문자 4건
- 구성·정보 밀도 저하 3건
- 중복 문자 3건
- 비승인 문자 2건
- 승인 문구 누락 2건
- 임의 기호 2건
- 오탈자 1건
- 계획되지 않은 말풍선 1건

Flash는 일부 장면에서 얼굴과 한국어 표기가 더 좋았지만, 그 장면을 생성 전에 안전하게 예측할 공통 속성을 찾지 못했다. 같은 데이터랩·관제실·교실 장면 안에서도 중복, 누락, 빈 표면, 임의 수치가 번갈아 발생했다. 결과를 본 뒤 좋은 모델을 고르는 것은 운영 라우팅이 아니며 2배 비용과 후처리 지연을 상시 발생시킨다.

## 5. Pro Priority 확정 근거

1. **동일 장면 직접 비교**: Pro 24 대 Flash 10으로 Pro 우세.
2. **가용성**: Pro 46/47, Flash 45/47. 큰 차이는 아니지만 Pro가 열세가 아니다.
3. **속도**: 성공 중앙값 Pro 36.41초, Flash 46.77초. p95도 Pro 54.05초, Flash 68.60초다.
4. **승인 문구 OCR 확인**: Pro 8장, Flash 4장. OCR 재현율 자체는 불완전하지만 동일 검사에서 Pro가 더 안정적이었다.
5. **정보 밀도와 Job52 계열 표현**: 둘 다 통과한 장면에서도 Pro가 장면 의미를 더 밀도 있게 구성한 경우가 많아 pairwise 우세가 컸다.
6. **라우팅 불가능성**: Flash 승리 장면을 `scene_type`, 의상, 배경, 텍스트 유무로 사전 분류하는 재현 가능한 규칙이 없다.
7. **Priority 운영성**: Pro는 공식 Priority inference와 실제 `serviceTier=priority` 응답 증거가 있으며 Flash에는 Priority가 없다.

## 7. 운영 반영 상태

- 현재 Docker 공통 경로에 적용된 `gemini-3-pro-image + Priority`를 유지한다.
- Flash 자동 폴백은 추가하지 않는다.
- 이번 전수 육안 작업에서는 API 호출, 서비스 재시작, 추가 운영 코드 변경을 하지 않았다.
- 아직 커밋·푸시는 하지 않았다. 기존 미커밋 변경과 이번 원장·문서가 함께 남아 있다.
- 다음 코드 작업은 모델 비교가 아니라 공통 품질 게이트 개선으로 전환한다.
