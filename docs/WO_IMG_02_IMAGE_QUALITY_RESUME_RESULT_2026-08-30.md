# WO-IMG-02 이미지 생성 개선 재개 결과

작성일: 2026-08-30
적용 대상: 영상 생성 버튼이 타는 공통 대본→이미지 계약 경로
유료 API 호출: 0회

## 1. 결론

운영 모델은 재검토하지 않고 `gemini-3-pro-image` + Priority로 유지했다. Flash는
연구 코드에만 남아 있으며 자동 폴백이나 운영 혼합에는 연결하지 않았다.

이번 작업으로 승인 내레이션에서 추출한 여러 화면 문구를 이미지 생성 전에 의미
사물과 물리 표면 후보로 자동 배정하는 공통 계획기의 1단계를 구현했다. 예를 들어
기업 두 곳은 좌우 비교 소품, 시장 지수와 그 결정론 수치는 중앙 요약 모니터의
서로 겹치지 않는 영역으로 계획된다. 특정 job ID나 scene 번호는 사용하지 않는다.

다만 생성된 이미지 픽셀에서 여러 표면의 실제 좌표를 자동으로 찾아 각각의 의미
ID와 결박하는 후단은 아직 완료되지 않았다. 현재 로컬 attestation은 표면 한 개만
안전하게 자동 결박하며, 여러 표면이면 명시 좌표가 없을 때 fail-closed한다. 따라서
이번 완료 범위는 **생성 전 의미 배정과 프롬프트 연결**이고, 생성 후 다중 픽셀 결박은
다음 독립 단계다.

## 3. 다중 표면 자동 계획

### 3.1 입력과 보존 규칙

`attach_scene_screen_texts()`는 승인 내레이션 원문을 바꾸지 않고 정확히 추출된
`screen_texts`만 사용한다. 사람이 만든 명시 계획은 그대로 보존하며, 자동 계획만
새 버전으로 다시 계산한다.

자동 계획은 문구를 다음 의미 역할로 분류한다.

- 등록된 회사: `company`
- 등록된 지수·거래소: `market_index`
- 숫자가 있는 승인 사실: `numeric_fact`
- 그 밖의 승인된 짧은 개념어: `context_label`

### 3.2 공통 배정 규칙

- 비교 회사가 둘 이상이면 `comparison_prop_left`, `comparison_prop_right`처럼 서로
  다른 소품 표면에 배정한다.
- 시장 지수와 결정론 수치는 `summary_monitor`를 공유할 수 있으나, 각 항목에는
  겹치지 않는 상대 영역을 부여한다.
- 개념어들은 `context_sign_1`, `context_sign_2`처럼 서로 다른 장면 소품 후보에
  배정한다.
- 모든 항목에 `semantic_object_id`, `surface_id`, `surface_kind`, `capacity`,
  `max_occurrences`를 남겨 후단 계보와 검증에 사용한다.

이 ID는 픽셀 좌표가 아니다. 이미지 생성 전 Gemini가 필요한 사물과 표면을 장면에
만들도록 하는 의미 계약이다. 생성 후 실제 위치를 추측해서 렌더하지 않는다.

### 3.3 Job52 계열 예시

`삼성전자`, `SK하이닉스`, `코스피`, `143조 원`이 승인 원문에 있을 때 계획은 다음과
같다.

1. `삼성전자` → `comparison_entity_1` / `comparison_prop_left`
2. `SK하이닉스` → `comparison_entity_2` / `comparison_prop_right`
3. `코스피` → `market_summary` / `summary_monitor` 상단 영역
4. `143조 원` → `market_summary` / `summary_monitor` 하단 영역

최종 Gemini 프롬프트에서는 결정론 수치 `143조 원`이 제거되지만 위 표면 ID와 의미
구조는 남는다. 따라서 모델에게 금융 숫자를 쓰게 하지 않으면서도 “두 비교 대상과
시장 전체 요약”이라는 장면 관계를 잃지 않는다.

## 4. 운영 버튼 경로 연결

공통 `ImagesWorker`는 다음 순서로 실행한다.

1. `attach_scene_screen_texts()` — 승인 문구와 자동 의미 표면 계획
2. `attach_v5_scene_contracts()` — archetype·소품·화풍·고정 Pro 모델 계약
3. `prompt_for_scene()` — V5 프롬프트 경계
4. `_bounded_text_generation_prompt()` — 수치·비승인 엔티티·배열/JSON형 문자 지시 제거
5. Gemini Pro Priority 호출
6. OCR·시각 QA·표면 attestation·결정론 오버레이

스크립트 워커에서도 같은 문구 계획기를 사용하므로 파일럿 스크립트에만 붙은 패치가
아니다. 다만 승인 대본/TTS/자막 원문은 변경하지 않는다.

## 5. 검증

### 선행 실패 계약

- 자동 계획 함수가 없을 때 scene07 계열 네 문구를 의미 사물별로 배정할 수 없었다.
- 좌표 없는 동일 `main` 표면 공유는 기존 공통 게이트가 이미 거절한다.

### 수정 후 집중 검증

- 호스트: 관련 계약 67 passed, 1 skipped
- 운영 Docker 재빌드 후: 98 passed
- 컨테이너: healthy
- 실제 통합 회귀에서 `143조`는 최종 Gemini 프롬프트에 없음
- 같은 회귀에서 `comparison_prop_left`, `comparison_prop_right`, `summary_monitor`는
  최종 프롬프트에 존재
- 같은 장면의 `image_profile.model`은 `gemini-3-pro-image`

Docker의 `test_character_face_reference_v2.py`는 이번 변경과 무관한 과거 스크립트가
컨테이너 외부 저장소 깊이를 `Path.parents[3]`로 가정하여 수집되지 않았다. 이 사실을
숨기지 않고 해당 파일을 제외한 실제 운영 의존성 묶음 98건을 다시 실행했다. 호스트
환경에서는 같은 얼굴 계약 테스트가 별도 의존성 조건 아래 이미 존재한다.

## 6. 비판적 한계와 다음 순서

이번 계획기는 역할 기반의 공통 하한선이지 모든 경제 개념의 완전한 의미 이해기가
아니다. 특히 회사가 아닌 복잡한 인과 사물, 세 개 이상의 비교 대상, 문서·계기·지도
같은 archetype별 최적 표면 선택은 더 확장해야 한다.

다음 순서는 다음과 같다.

1. 다중 표면 로컬 검출 결과를 각 `surface_id`에 안전하게 연결하는 후단 구현
2. 여러 후보가 있을 때 순서를 추측하지 않도록 시각 특징·표면 종류·계획 의미의
   일치 attestation 추가
3. 얼굴 4영역과 해부학 하한선의 Pro 전수 원장 재평가
4. 레퍼런스 채널 배경 유형을 archetype 선택기의 보조 근거로 연결
5. 모든 정지 이미지 게이트를 통과한 장면만 Fal 국소 모션 후보로 전달

유료 API는 이번 작업에서 호출하지 않았다. 다음 실제 canary는 생성 후 다중 표면
결박까지 준비된 뒤 별도 승인 범위에서 수행한다.

## 7. 세 가지 큰 목표와의 관계

1. **시간·분량·TTS·자막·이미지 싱크**: 승인 대본을 단일 기준으로 유지하고 문장·수치
   자체를 바꾸지 않았으므로 기존 청크 동기화를 훼손하지 않는다.
2. **대본 의미를 충실히 설명하는 이미지**: 여러 문구를 하나의 보드에 몰지 않고
   비교 대상과 요약 정보를 서로 다른 의미 사물에 배치하는 생성 전 구조를 추가했다.
3. **오탈자·이탈자·수치 정확성**: 숫자는 Gemini에서 제거하고, 비승인 숫자는 OCR로
   거절하며, 승인 문자열의 표면과 허용 횟수를 계보로 남긴다.

따라서 Job52의 만족 요소인 정보 밀도와 사물 비유는 살리면서, 불만족 요소였던 단일
보드 몰아넣기·임의 수치·표면 의미 불명확을 공통 경로에서 줄이는 방향이다. 아직
생성 후 다중 표면 좌표 결박이 남아 있으므로 “완료”가 아니라 1단계 완료로 판정한다.
