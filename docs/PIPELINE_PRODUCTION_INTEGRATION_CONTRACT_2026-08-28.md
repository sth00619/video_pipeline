## 1. 가장 중요한 결론

`요청할 때마다 적용한다`는 말은 같은 이미지나 같은 상황을 다시 만든다는 뜻이 아니다.
사용자가 UI에서 영상 생성을 시작할 때 실행되는 공통 파이프라인이 다음 계약을 매번 적용한다는 뜻이다.

1. 승인 대본 원문과 TTS·자막·장면 의미의 계보를 해시로 고정한다.
2. 각 장면은 그 장면의 대본 의미에 맞는 구도·소품·표현을 새로 선택한다.
3. Job52에서 확인한 화풍과 캐릭터 얼굴 범위는 참조 자산으로 사용하되, Job52의 배경·의상·문구·구도를 복제하지 않는다.
4. 금융 수치와 정보성 문자열은 근거에서 정확히 가져와 결정론적으로 렌더링하고, 생성 모델의 의사문자·오탈자·이탈자를 엄격하게 거절한다.
5. Fal은 수치·문자 표면을 움직이지 않고, 안전 판정을 통과한 캐릭터·사물·배경에만 적용한다.

제품 코드에 `job_id == 52`, `scene == 7` 같은 운영 분기를 두지 않는다. Job52 scene 번호는 테스트 이름과 증거 문서에서 실패를 재현하기 위한 식별자일 뿐이다.

    G --> H["NanaBananaProvider<br/>Gemini POST 직전 계약 주입"]

실제 연결점은 다음과 같다.

| 계층 | 운영 파일/호출 | 공통 계약 |
|---|---|---|
| UI | `frontend/src/pages/JobNew.jsx`, `JobDetail.jsx` | Job 생성 및 단계별 생성 API 호출 |
| Spring | `ImagesService.java` → `FastApiClient.generateImages()` | 저장된 SCRIPT/TTS 메타와 예산 정책 전달 |
| FastAPI 입구 | `app/main.py`의 `/workers/images/generate` | 모든 이미지 Job을 같은 `ImagesWorker.generate()`로 전달 |
| 장면 계보 | `app/workers/images_worker.py` | 승인 대본↔TTS 원문, 자막 청크↔장면 경계, 장면 의미 해시 검증 |
| 프롬프트 | `_bounded_text_generation_prompt()` | 정보성 문자열·수치 정책, 장면별 의미·텍스트 허용 범위 적용 |
| 참조 선택 | `select_contextual_reference_paths()` | 주제에 따라 반도체·시장 흐름·위험 날씨·브리핑 참조를 선택하고 얼굴 v2/역할 기준점 결합 |
| 실 API 직전 | `NanaBananaProvider._generate_gemini_api()` | `ensure_gemini_reference_contract()`를 호출한 뒤 실제 payload와 해시 생성 |
| 정지 이미지 QA | `inspect_visible_text()` 및 V5 표면/오버레이 게이트 | 비승인 문자, 훼손 수치, 잘못된 위치, 빈 물리 표면을 fail-closed 처리 |
| 모션/조립 | `fal_motion_safety.py`, `longform_worker.py` | 문자·수치 모션 차단, 조립 직전 SCRIPT/TTS/자막/장면 계보 재검증 |

`JobDetail.jsx`의 수동 재생성 버튼은 별도 HTTP endpoint를 사용하지만, 이제 같은 `ImagesWorker` 공통 계약을 호출한다. 따라서 자동 Workflow, 수동 단계 실행, 과거 Job 재개, 단일 장면 재생성이 서로 다른 품질 규칙을 사용하지 않는다.

각 단계 응답과 manifest에는 `operational_contract_audit`가 저장된다. 버전은 `video-button-global-v1-20260828`, 범위는 `all_jobs_all_topics`, `job_specific_patch`는 항상 `false`다. 이 필드는 코드가 존재한다는 주장보다 강한 사후 증거로, 새 Job의 실제 자산이 어느 계약과 판정을 거쳤는지 확인하는 용도다.

## 3. 이번 추적에서 발견한 실제 운영 누락과 수정

### 3.1 발견한 누락

Job52 기반 얼굴 참조 v2와 정밀 얼굴 계약은 파일럿용 `GeminiProvider.generate()` 안에는 있었지만, 영상 생성 버튼의 운영 경로가 실제로 사용하는 `NanaBananaProvider._generate_gemini_api()`에는 항상 들어가지 않았다.

그 결과 참조 PNG 자체는 전송돼도 모델이 각 참조의 역할을 알 수 없었다. 이 상태에서는 다음 문제가 다양한 주제에서 재발할 수 있었다.

- 얼굴 범위 참조를 단순 화풍 이미지처럼 평균냄
- 작은 검은 타원 눈, 흰자 소실, 과도하게 각진 눈썹
- 장면 의상까지 얼굴 정체성으로 오해해 모든 장면을 비슷하게 만듦
- 국소 재생성의 첫 실패 프레임을 캐릭터 정체성 참조로 오해함

### 3.2 공통 경로 수정

`ensure_gemini_reference_contract()`를 실 API POST 직전에 호출하도록 옮겼다. 이 함수는 다음 실행 경로에서 공통으로 작동한다.

- 신규 영상 Job
- 과거 Job 재개
- 병렬 이미지 생성
- 순차 이미지 생성
- 단일 장면/국소 재생성
- V5 계약 선언이 있는 요청과 과거 선언 없는 요청

송신 프롬프트에는 `job52-range-v2-operational-v2` 계약 버전이 포함된다. v2는 동전 하나가 머리이자 몸통 전체인 실루엣, 테두리에 붙은 짧은 팔다리, 별도 인간 몸통·긴 인간 다리 금지를 명시한다. 향후 Job의 request audit에서 payload hash와 함께 이 버전이 존재하는지 확인할 수 있다.

계약은 얼굴을 하나의 고정 표정·의상으로 복사하지 않는다. 승인된 여섯 얼굴의 공통 조형 범위만 유지하고, 표정·의상·행동·배경·구도는 현재 장면 대본이 결정한다. 국소 재생성에서는 첫 첨부 이미지를 수정 원본으로 명시하고 캐릭터 정체성 참조로 사용하지 않는다.

| 1. YouTube→검증 대본→분량/TTS/자막/이미지 의미 동기화 | 약 65~70% | 23개 언론사 근거와 승인 대본을 만들더라도 TTS 청크·이미지 전환이 다른 문장을 가리키면 실제 영상은 틀리므로, 승인 원문·청크·장면 해시를 이미지와 조립 단계까지 연결했다. | 다양한 주제의 신규 약 5분 Job에서 검색 근거, 대본 길이, TTS 실제 시간, 자막 청크, 장면 전환이 함께 통과 |

## 6. 테스트와 실제 테스트의 역할

- Job52: 만족/실패 기준을 제공하는 회귀 fixture
- scene02·07·35·47: 원인을 재현하는 대표 fixture
- 오프라인 테스트: API 비용 없이 계약 우회와 회귀를 차단
- 소규모 Gemini 실 API: 실제 공급자 payload, 사용량, 얼굴/텍스트 물리 결과 검증
- 신규 5분 E2E: 다양한 대본에서도 공통 계약이 실제 영상 생성 버튼 경로에서 유지되는지 최종 검증
- 1분 Fal 파일럿: 정지 이미지 승인이 끝난 뒤에만 모션 안전성과 자연스러움 검증

테스트 전용 코드가 통과했다고 목표를 완료하지 않는다. 테스트가 증명한 계약이 실제 HTTP 송신 경계와 UI Workflow에 연결돼 있고, 신규 주제 Job의 원장과 결과물에서 다시 관측될 때만 운영 반영으로 인정한다.
